# Опубликовать веб-интерфейс за обратным прокси

`dsh --profile web` Он обслуживает графический интерфейс на порте обратной связи, поэтому браузер на другом компьютере не может достичь его, и процесс ничего не знает об используемом вами адресе. Обратный прокси-сервер перед ним владеет этим внешним ногом — публичным именем хоста, TLS и префиксом пути, который он полосает перед переадресацией слушателю, — и `--public-url` сообщает DSH, какой адрес используют браузеры:

```sh
dsh --profile web --public-url https://app.example/ui/ --trusted-host app.example
```

<a id="what---public-url-advertises"></a>

## Что? `--public-url` реклама

`--public-url` принимает корень `http://` или `https://` с дополнительным монтируемым префиксом и нормализует его до окончания в `/`. Он предоставляет распечатанный и открытый URL-адрес запуска, `DSH_WEB_URL`и URL-адрес Web GUI в контексте среды выполнения агента. Веб-сервер продолжает обслуживать маршруты исходного кода и никогда не узнает гору. Поле конфигураций `publicUrl` публикует ту же рекламу.

<a id="what-the-proxy-must-do"></a>

## Что должен делать прокси

- **Сохранить браузер лицом `Host`.** Забор сравнивает полученный `Host` против принятых властей, поэтому прокси пересылает его без изменений вместо того, чтобы переписывать его на адрес слушателя.
- **Разрежьте префикс крепления.** Слушатели отвечают на маршруты происхождения, поэтому запрос на `/ui/api/...` должен прибыть как `/api/...`.
- **Вперед, модернизация.** Каждый запрос и обновление WebSocket, открываемые на странице, должны доходить до слушателя. `Upgrade` и `Connection` Заголовки неповрежденные; TLS заканчивается на внешней ноге прокси, когда он обслуживает HTTPS.
- **Перезаписывайте объем cookie.** A backend, обслуживающий простые HTTP-файлы только для хоста `Path=/` cookie без `Secure`; прокси затем переписывает `Path` на монтировку (`/ui/`) и добавляет `Secure` на ногу HTTPS. Бэкэнд-слушатель, обслуживающий свой собственный TLS, уже отмечает файл cookie `Secure`, поэтому прокси-сервер только переписывает `Path`.
- **Перенаправить голую гору.** `/ui/` является единственной записью: только он обменивает стартовый токен на файл cookie сессии, и он или `/ui/index.html` обслуживает документ в браузере, который уже содержит этот файл cookie, потому что обслуживаемый документ разрешает URL-адреса против своего собственного каталога. Запрос на `/ui` должен поступать как `/ui/`, и полосатый бэкэнд не может реконструировать этот внешний путь.

<a id="trust-the-authority-browsers-use"></a>

## Доверяйте авторитету, который используют браузеры

Забор принимает обратную связь, собственный адрес связи слушателя и имена всех авторитетов `--trusted-host` . Браузер, который достигает развертывания под любым другим органом, получает 403 для каждого вызова API, как бы ни был правильный прокси-сервер, поэтому назовите авторитет браузера с `--trusted-host`; реклама его с `--public-url` отображается только и не допускает этого. Вход без порта соответствует любому порту, который подходит для туннеля, который каждый раз связывает другой. Забор принимает только запрос; токен запуска в распечатанном URL-адресе и подписанный файл cookie сеанса аутентифицируют его. TLS, где бы он ни заканчивался, ничего из этого не меняет: сертификат идентифицирует сервер с браузером, а не браузер с сервером.

Ни рекламируемый URL-адрес, ни забор не защищают сам порт прослушивания, поэтому ограничьте порт доверенным прокси-сервером или сетью.

<a id="secure-the-external-leg"></a>

## Защищайте внешнюю ногу

Прекратите TLS по доверенности, на самом слушателе или на обоих; `--public-url` остается рекламой. Корень, обращенный к браузеру `http://` , раскрывает маркер запуска в простом тексте. Корень прокси `https://` защищает ногу браузер-прокси; шифрование между прокси и слушателем зависит от конфигурации TLS слушателя.

Чтобы закончить на слушателе, пройдите `--tls-cert` и `--tls-key`, каждый путь решен против рабочего каталога процесса: файл сертификата содержит полную цепочку, а файл ключа - незашифрованный PEM-ключ. DSH никогда не получает, не обновляет и не смотрит сертификаты, а носитель считывает файлы один раз, поэтому замените их и перезагрузите слушателя или перезапустите процесс, чтобы изменить их; запуск не удается на отсутствующей или недействительной паре и никогда не возвращается к HTTP. Браузер применяет свой собственный магазин доверия и проверки имени, поэтому сертификат должен охватывать имя хоста или IP, который вы открываете. Порт по умолчанию остается 3080. Native TLS не нуждается в прокси-серверах, но развертывание прокси-серверов и `--public-url` поддерживаются независимо. Прослушатель TLS отмечает сеансовые куки `Secure`; держите общедоступный HTTPS, обращенный к браузеру, чтобы браузеры могли вернуть эти куки.

Распечатанный URL-адрес несет в себе учетные данные процесса, поэтому делитесь им только с предполагаемыми пользователями.

The [Ссылка на веб-приложение](../../../packages/bundle/web-app/README.md#public-deployments) документы `--public-url`, `--trusted-host`и `--tls-cert`/`--tls-key` Варианты командной строки в веб-профиле, `publicUrl` сконфигурировать `web-runtime` ряд, `trustedHosts` сконфигурировать [Связной ряд](../../../packages/client/connection/README.md)и `tls` сконфигурировать [строка webserver](../../../docs/subsystems/web-server.md#config).
