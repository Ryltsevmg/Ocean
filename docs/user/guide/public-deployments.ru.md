# Публикация веб-интерфейса через обратный прокси

Команда `dsh --profile web` обслуживает веб-интерфейс на локальном порту loopback. Браузер на другом компьютере не может подключиться напрямую, а процесс не знает внешний адрес. Обратный прокси обслуживает публичное имя хоста и TLS, а перед пересылкой запроса удаляет префикс пути. Параметр `--public-url` сообщает DSH, по какому адресу браузеры открывают интерфейс:

```sh
dsh --profile web --public-url https://app.example/ui/ --trusted-host app.example
```

<a id="what---public-url-advertises"></a>

## Где используется `--public-url`

Параметр `--public-url` принимает базовый URL с `http://` или `https://` и необязательным префиксом пути. Он добавляет завершающий `/`, задаёт URL, который DSH выводит и открывает при запуске, значение `DSH_WEB_URL` и адрес веб-интерфейса в контексте агента. Внутренний сервер обслуживает маршруты от корня и не учитывает внешний префикс. Поле `publicUrl` задаёт тот же внешний адрес.

<a id="what-the-proxy-must-do"></a>

## Что должен делать прокси

- **Сохранять полученный от браузера заголовок `Host`.** Сервер сверяет полученный `Host` с разрешёнными адресами. Прокси передаёт заголовок без подмены адресом внутреннего сервера.
- **Удалять префикс пути.** Внутренний сервер обслуживает маршруты от корня, поэтому запрос к `/ui/api/...` должен поступить как `/api/...`.
- **Передавать запросы на переключение протокола.** Все запросы, включая переход на WebSocket, должны доходить до сервера с исходными заголовками `Upgrade` и `Connection`. Если прокси обслуживает HTTPS, на стороне браузера TLS завершается на прокси.
- **Корректировать область действия cookie.** Внутренний сервер по HTTP выдаёт cookie для текущего хоста с `Path=/` без `Secure`. Прокси заменяет `Path` на внешний префикс (`/ui/`) и добавляет `Secure` на стороне HTTPS. Если внутренний сервер сам использует TLS и ставит `Secure`, прокси меняет только `Path`.
- **Перенаправлять запрос без завершающей косой черты.** Только `/ui/` обменивает токен запуска на cookie сессии. Браузер с этим cookie может загрузить документ по этому адресу или по `/ui/index.html`, поскольку относительные URL вычисляются от каталога документа. Прокси перенаправляет запрос с `/ui` на `/ui/`. После удаления префикса внутренний сервер не может восстановить внешний путь.

<a id="trust-the-authority-browsers-use"></a>

## Разрешите адрес, используемый браузером

Сервер принимает адреса loopback, свой адрес прослушивания и адреса из `--trusted-host`. При обращении через другой адрес все запросы API получат ответ 403 даже при правильной настройке прокси. Добавьте видимый браузеру адрес в `--trusted-host`. Параметр `--public-url` только задаёт отображаемый адрес. Запись без порта подходит для любого порта, в том числе если туннель выбирает его при каждом запуске. Проверка хоста допускает запрос, а токен запуска из выведенного URL и подписанный cookie сессии обеспечивают аутентификацию. TLS подтверждает браузеру подлинность сервера, но не аутентифицирует браузер.

Ограничьте доступ к порту прослушивания доверенным прокси или сетью. Внешний URL и проверка хоста сами порт не защищают.

<a id="secure-the-external-leg"></a>

## Защитите соединение с браузером

Настройте завершение TLS на прокси, на внутреннем сервере или на обоих. Параметр `--public-url` по-прежнему только задаёт внешний адрес. Публичный адрес с `http://` передаёт токен запуска открытым текстом. Адрес с `https://` защищает соединение от браузера до прокси. Шифрование между прокси и сервером зависит от настройки TLS на внутреннем сервере.

Для TLS на внутреннем сервере передайте `--tls-cert` и `--tls-key`. Пути отсчитываются от рабочего каталога процесса. Файл сертификата должен содержать полную цепочку, а файл ключа — незашифрованный закрытый ключ PEM. DSH не получает и не обновляет сертификаты и не отслеживает изменения файлов. Он считывает их один раз, поэтому после замены перезагрузите сервер или перезапустите процесс. При отсутствующей или недействительной паре запуск завершится ошибкой без перехода на HTTP. Браузер проверяет имя и доверие к сертификату. Сертификат должен покрывать открываемое имя хоста или IP-адрес. Порт по умолчанию — 3080. TLS на сервере работает без прокси. Прокси и `--public-url` можно настроить независимо. Сервер с TLS добавляет `Secure` к cookie сессии. Сохраняйте HTTPS на публичном адресе, чтобы браузер мог вернуть cookie.

Выведенный URL содержит токен доступа к процессу. Передавайте его только тем, кому нужен доступ.

В [справке по веб-приложению](../../../packages/bundle/web-app/README.md#public-deployments) описаны параметры `--public-url`, `--trusted-host` и `--tls-cert`/`--tls-key`. В веб-профиле `publicUrl` настраивает запись `web-runtime`, `trustedHosts` — [запись Connection](../../../packages/client/connection/README.md), а `tls` — [запись webserver](../../../docs/subsystems/web-server.md#config).
