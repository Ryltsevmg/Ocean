## インフォメーション

チャットでモデルを尋ねて、リマインダーを作成、リスト、ビュー、編集、一時停止、再開、または削除します。 各リマインダーはルールによって繰り返され、既存の会話に指示を届け、新しい会話を1つに、またはあらゆる場面で新しい会話に配信します。 オートメーションタスクページでは、ホストのすべてのリマインダーをリストし、作成、編集、実行、一時停止、再開、削除することができます。 1ショットのタスクを明示的に削除するまで、利用可能なままに配信しました。

## タスクを編集する

リマインダーの名前、指示、繰り返しルール、または配信対象を変更したり、一時停止または再開したりするモデルを尋ねます。変更はリマインダーIDと保存された配送記録を保持します。

オートメーションタスクでは、タスクを選択して、自動化タスク名、オートメーションタスクの指示、実行、リンクされたワークスペース、および実行時間を変更します。 変更を保存を選択するまで、編集はローカルの草案に滞在します。 編集は、タスクID、最新の配信レシート、保存されたすべての配送記録を保持します。 変更されたルールは、タスクを再び有効化し、パユースされたタスクを再利用する。 既存の会話に配信するタスクのために、現在のリンクされた会話を表示して実行します。別のオプションを選択すると、後で会話を作成し、リンクされたワークスペースを初期値に設定します。 タスクは、ワークスペースが同じままに保存されたプリセットを保持します。 変更されたワークスペースはデフォルトのプリセットを使用します。

- 一度: 日付は月カレンダーを開き、時刻は時間、分、秒単位、タイムゾーンはそれらを解釈します。タスクは一度実行し、終了します。
- N 分毎と N 時間ごとに: インターバルは、タスクを節約する分数または時間数を設定します。 間隔は、タスクを節約する分からカウントします。
- 毎日: インターバルは日数を設定し、時間と分数の列を開きます。
- 週・月曜日から金曜日まで: インターバルは週数を設定し、平日は日数を選択し、時間、分数、秒数の列を開きます。 月曜日から金曜日までは、一度に5日間選択します。
- 毎月: インターバルは、月々の日が1から31日までの日付を選択し、時間、分岐、秒次列を開きます。 選択した日付のない月は、その最終日に実行されます。
- カスタム: カスタムルールはルールテキストを保持します。 他の選択肢がカスタムで開くことができないルール。 編集可能なルールテキストのない既存のタスクは、元の周波数を表示し、交換を保存するまでそのタイミングを保持します。

タイムゾーンは、最近選択したゾーンを最初に表示し、システムゾーンをマークし、UTCオフセット、IANA ID、または都市で検索します。 別のゾーンを使用するガイドされた選択肢とカスタム式が表示されます。 それ以外の場合は、カスタムルールテキストはゾーンを供給します。

フィールドはローカルドラフトだけを変更します。 タスクが既存の会話をターゲットにしている場合、現在のリンクされたセッションは利用でき、他の編集を破棄することなく目的地の変更を解除できます。 編集中は、詳細の一番下は、Discover と Save の変更が示されています。変更を保存すると、変更されたフィールドのみが 1 つの更新で送信され、Discover は保存された値を復元します。 変更したタイミングだけ新しい規則を送信します。 変更を保存して、重要な変更が有効なフィールドとタイミングを持つまで無効にします。 無効なカスタムテキストは、ドラフトを保持し、補正メッセージを表示させます。また、ホストは保存のルールを検証します。 保存または破棄される変更まで、今、使用、再開、および削除の待ち時間を節約できます。 保存中にフィールドが無効になっています。 詳しくは、ホストの書き込みを既に開始しないロールバックしません。

タスクを切り替えたり、ページを離れたりすると、未保存のドラフトが保存されます。 カタログは、プリスチンフォームを更新します。編集されたフォームは、すべてのフィールドとその元のバージョンを維持します。 配信または別の編集がタスクを変更した場合、タスクが他の場所を変更し、新しいバージョンが到着したときに変更を保存しないという詳細の状態。 Host は、保存時にバージョンもチェックします。 私の編集でレビューすると、変更したタイトル、プロンプト、タイミング、およびターゲットグループが他のグループの最新値を読み込んでいます。 保存する前にフォーム全体を確認する; このアクションは単独で保存しません。 同じグループが他の場所で変更された場合、編集はフォームに優先されます。 Discardは、最新の保存値で全草案を置き換えます。 別の保存が失敗した場合、ドラフトは滞在し、詳細は再び試してみてください。結果が不明な更新を再試行する前にタスクを確認してください。 受付けたアップデートで、カタログが更新されます。 閉じた後の応答を遅くするか、タスクを切り替えると、現在のビューを置き換えません。

## タイミングおよび配達参照

セッションが開かない場合は、リマインダーが保存されます。 ホストが実行している間、リマインダーが期限切れになると、ターゲットセッションを復元または作成し、現在の作業を中断することなくフォローアップをキューに入れます。 保存されたタスクを再起動し、オーバーデューワンショットまたは各再発タスクの最新の欠落した発生だけを送信します。 ホストの終了は、開始までスケジュールを停止します。 同じセッションで再発するタスクは、1つのメッセージを共有できます。

IANAゾーンの繰り返しルールは、ローカルウォールタイムを追っていきます。ローカルタイムをスキップして、ローカルタイムを繰り返すことはありません。 既存のタスクは、新しいルールを保存するまでのタイミングを維持します。固定レートリマインダーは、その作成時間と毎日、毎週、またはcronリマインダーは、IAAゾーンで保存されたローカルタイムに従います。 ブラウザは、自然言語の要求を解釈するためのゾーンを供給します。 ゾーンを明示的にエンゲージすることは、曖昧さを回避します。 自動化タスクページでは、ブラウザのタイムゾーンと異なる場合、次の実行をブラウザゾーンクロックとして表示し、周波数テキスト名はルールのゾーン名です。ゾーン名がブラウザのゾーンを使用するルールです。

保存された配信レコードは、モデルが要求された作業を完了していない、会話受信トレイで主張されたメッセージを確認します。 失敗した受信トレイの永続性またはタスクの書き込みは保存されたレコードを追加しません。 受信トレイの永続後、クラッシュまたはタスク書き込みの失敗は、配信されたメッセージが記録されていないままになり、配達を繰り返すことができます。 正確にオンス配送は保証されません。 ホストは、会話受信トレイで待機しているメッセージごとに破棄します。保存されたレコードは残っていますが、このモデルはメッセージを受け取ることはありません。そして、ホストは再び送信しません。 これは、実行履歴または外部通知チャネルではありません。

認識が承認されると保存されたレコードが実行されます: ホストは、確認された時間が設定された内部に落ちるレコードを保持します `deliveryHistoryDays` ウィンドウは、付属のレシートから戻って測定 `deliveredAt`、そして最も最新式の `deliveryHistoryRecords` レコード。 最新のレシートは、常に生き生き残り、剪定されたウィンドウは、使用不能の以前のレコードをマークします。 ホストは、記憶に残された歴史を保ち、各認識のための完全なタスク行を書き換えます。 保存された履歴や指示バイトではなく、返されたレコード数を制限します。

名前、命令、タイミング、およびターゲット編集、パワシ、および再開は、 `schedule_edit` およびあらゆるリマインダーのためのオートメーションのタスク ページを通してモデルに利用できます;交差セッションのリレー ワークフローは両方あります。 変更は、変更を行った会話以外に、エージェントが読み込まれた各会話の次のモデルリクエストに通知を追加します。 古いセッションログにのみ記録されたリマインダーは、自動的にスケジュールされません。必要なものを再作成します。 以前削除されたタスクレコードは再構築されません。
