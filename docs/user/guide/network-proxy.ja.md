# ネットワークプロキシ経由で OCEAN を実行する

<!-- USER_LANGUAGES_START -->
[English](network-proxy.md) | [中文](network-proxy.zh.md) | [Русский](network-proxy.ru.md) | 日本語 | [Español](network-proxy.es.md) | [Français](network-proxy.fr.md) | [Deutsch](network-proxy.de.md) | [Português](network-proxy.pt.md) | [한국어](network-proxy.ko.md)
<!-- USER_LANGUAGES_END -->

OCEAN はモデル呼び出し、ウェブ検索、ページ取得、HTTP 経由の MCP サーバーへの接続を、標準のプロキシ環境変数で指定したプロキシに送ります。OCEAN は起動時に環境変数を読み取ります。追加の設定は不要です。設計上またはランタイムの制約によって直接接続する経路は、後述の「プロキシを経由しない接続」に記載しています。

<a id="export-the-variables"></a>

## 変数をエクスポートする

```sh
export HTTPS_PROXY=http://127.0.0.1:7890
export HTTP_PROXY=http://127.0.0.1:7890
```

すべての `ocean` コマンドで設定を引き継ぐには、上の 2 行をシェルのプロファイルに追加するか、`$OCEAN_HOME/.env`（既定では `~/.ocean/.env`）に API キーとともに設定します。シェルからエクスポートした変数がファイルの設定より優先されます。プロジェクトの `.env` は `git clone` で取得されます。リポジトリが通信先を指定できないよう、そこにプロキシ変数が設定されていると OCEAN は起動を拒否します。

認証が必要な場合は、`http://user:password@proxy.example:8080` のように URL に認証情報を指定します。OCEAN は URL を出力せず、診断メッセージには拒否した変数の名前だけを表示します。ユーザー名とパスワードは表示されません。

<a id="why-your-browser-is-proxied-but-your-terminal-is-not"></a>

## ブラウザーとターミナルでプロキシ設定が異なる理由

OCEAN に限らず、すべてのソフトウェアが共通して使う「システムプロキシ」はありません。プロキシを設定する方法は 3 種類あります。

| 設定方法 | 適用対象 |
|---|---|
| OS のプロキシ設定 | Safari、ほとんどの macOS ネイティブアプリ、Chrome、Edge |
| `HTTP_PROXY` / `HTTPS_PROXY` 環境変数 | `curl`、`git`、`npm`、`pip`、OCEAN |
| TUN モード（仮想ネットワークインターフェース） | アプリ側の設定なしですべての通信に適用 |

Clash などのプロキシアプリで「システムプロキシ」をオンにすると、OS のプロキシ設定だけが更新されます。ブラウザーはその設定を参照しますが、コマンドラインツールには別途環境変数をエクスポートする必要があります。TUN モードなら、環境変数を設定せずに両方の通信をプロキシ経由にできます。

OCEAN は OS のプロキシ設定を読み取りません。環境変数をエクスポートするか、TUN モードを使ってください。

<a id="choose-what-stays-direct"></a>

## 直接接続するホストを指定する

`NO_PROXY` に、直接接続するホストを列挙します。

```sh
export NO_PROXY=internal.example.com,.corp.example.com,registry.local
```

各項目は、指定したホストとそのすべてのサブドメインに一致します。`NO_PROXY=example.com` を設定すると、`api.example.com` にも直接接続します。先頭に `.` や `*.` を付けても意味は変わりません。項目には `:port` を指定でき、`*` を指定するとすべての接続でプロキシを迂回します。

**CIDR 範囲は指定できません。** OS のプロキシ除外リストにある `10.0.0.0/8` や `192.168.0.0/16` を `NO_PROXY` にコピーしても効果はありません。ホスト名やドメインのサフィックスを使ってください。

`localhost` や `127.0.0.1` を指定する必要はありません。OCEAN は、自身の Web UI やローカルサーバーへの通信がプロキシを経由してループするのを防ぐため、ループバックには常に直接接続します。

<a id="limits-worth-knowing"></a>

## 制限と注意事項

**SOCKS プロキシには対応していません。** OCEAN は起動時に `socks5://` の値について報告し、その値をスキップして、該当するスキームには直接接続します。使用可能な `HTTP_PROXY` があっても、`HTTPS_PROXY=socks5://…` を設定すると `https:` は直接接続になります。環境変数にはプロキシアプリの HTTP ポートを指定してください。多くのアプリは両方のポートを提供し、HTTP ポートは通常 SOCKS ポートに近い番号です。

**`ALL_PROXY` だけでも設定できます。** OCEAN は HTTP と HTTPS のどちらにもフォールバックとして使います。Node や curl とは扱いが異なります。`HTTPS_PROXY` を明示すると設定の意図が分かりやすくなります。

**TLS 通信を検査する社内プロキシでは、その証明書が必要です。** プロキシに接続できても証明書エラーが発生する場合は、起動前に組織の CA バンドルを Node に指定してください。

```sh
export NODE_EXTRA_CA_CERTS=/path/to/corporate-ca.pem
```

Node はプロセスの起動時にだけこの変数を読み取るので、`ocean` を実行する前にエクスポートしてください。

**OCEAN が起動するツールにも同じプロキシ設定が渡されます。** bash ツールのコマンド、`git`、`gh`、子プロセスとして起動する MCP サーバーは、これらの環境変数を引き継ぎます。Node の子プログラムは、インストール済みの独自のランタイムを使います。Node 22.21 以降と Node 24 以降はこれらの変数を使用し、それより古いランタイムは直接接続します。SOCKS URL など OCEAN が拒否した値が含まれている場合、Node ベースのツールは起動に失敗せず直接接続します。`curl` と `git` はその値を引き続き読み取ります。

**プロキシ URL に含まれるパスワードもツールに渡されます。** `HTTPS_PROXY=http://alice:s3cret@proxy.example:8080` は通常の環境変数です。モデルが書いたコマンドを含め、OCEAN が起動するすべてのコマンドから読み取れます。環境変数を表示するコマンドを実行すると、保存される出力にパスワードが含まれます。シェルで実行するほかのコマンドでも同様です。これを避けるには、認証情報が不要なプロキシの接続先を用意するか、URL 以外の方法で認証してください。

<a id="what-stays-direct"></a>

## プロキシを経由しない接続

次のリクエストはプロキシを経由しません。

- **このマシン内の通信。** `localhost`、`127.0.0.0/8` の全範囲、`::1`、`0.0.0.0` への接続は常に直接行われます。ローカルでのみ待ち受けるサービスにはプロキシから接続できません。
- **モデルが書いたコード。** ワークフローのワーカーと Node の ptc-runtime プロセスにはプロキシ設定が渡されないため、スクリプトはパスワードを含み得るプロキシ URL を環境変数から読み取れません。プロキシが必要なら、リクエストを送るコードで設定します。実行サンドボックスの制約は引き続き適用されます。
- **利用状況のテレメトリー。** 同梱のプロファイルは OTel によるセッション送信を無効にしているため、プロキシを経由させるテレメトリー要求はありません。有効化したデプロイでは、プロキシ設定が届かない Node 自身の HTTP クライアントで送信するため、直接接続となり、外部への直接通信が遮断された環境では失敗します。
- **プライベート IP アドレスを直接指定する `web_fetch`。** `http://10.0.0.5/` のような URL は、プロキシ設定の有無にかかわらず拒否されます。

<a id="check-that-it-worked"></a>

## 動作を確認する

エージェントにページの取得を依頼し、プロキシアプリの接続ログを確認します。

```sh
ocean --profile headless "fetch https://example.com and tell me the page title"
```

ログにリクエストが表示されない場合は、OCEAN の環境に変数が引き継がれているか確認してください。

```sh
env | grep -i proxy
```
