## 요약

대화에서 모델에게 알림 생성, 목록 표시, 조회, 편집, 일시 중지, 재개, 삭제를 요청할 수 있습니다. 알림은 규칙에 따라 반복되고, 지시를 기존 대화, 첫 실행 때 만드는 새 대화, 또는 실행마다 만드는 별도의 새 대화로 전달합니다. 자동화 작업 페이지에서는 Host의 모든 알림을 보고 각각 생성, 편집, 실행, 일시 중지, 재개, 삭제할 수 있습니다. 한 번만 실행하는 작업도 전달 후 직접 삭제할 때까지 남습니다.

## 알림 만들기

함께 제공되는 Web 프로필에 Host의 일정 서비스와 자동화 작업 페이지가 포함됩니다. 알림을 만들도록 요청하기 전에 모델 제공업체를 설정하세요.

`standard`, `cordis`, `ptc` 프리셋은 모델에 현재 시각과 브라우저의 시간대를 알려 주는 컨텍스트와 네 가지 알림 도구인 `schedule_create`, `schedule_list`, `schedule_view`, `schedule_edit`를 제공합니다. `minimal`은 둘 다 제공하지 않습니다. 위임받은 하위 에이전트에게도 도구가 보이지만 호출은 거부되므로 알림을 읽거나 변경할 수 없습니다.

알림 생성에는 `schedule_create`, 모든 대화의 알림 목록에는 `schedule_list`, 개별 알림 조회에는 `schedule_view`, 변경·일시 중지·재개·삭제에는 `schedule_edit`를 사용합니다. 편집해도 알림 ID와 저장된 전달 기록은 유지됩니다. 모델이 만드는 알림에는 이름, 지시, UTC 또는 IANA 시간대의 시작 시각과 RFC 5545 반복 규칙이 있습니다. 예를 들어 평일마다 09:00에 반복하거나 한 번만 실행할 수 있습니다. 지시는 현재 대화, 첫 전달 시 만드는 대화 하나, 또는 매번 새로 만드는 대화에 전달됩니다. 새 대화는 현재 대화의 작업 디렉터리와 프리셋을 사용합니다. 다음 전달은 이전 전달 예정 시각 또는 이전 ‘지금 실행’ 시점으로부터 최소 1분 뒤에 이루어집니다. 매번 새 대화를 여는 알림에는 Host의 최소 실행 간격이 적용되며 기본값은 1분입니다. Host 재시작 등으로 전달이 늦어져도 다음 일정은 밀리지 않습니다.

전달 시 만들어진 대화는 작업 디렉터리에 등록된 워크스페이스에 들어가며 알림 이름을 제목으로 씁니다. 매번 새 대화를 여는 작업의 제목에는 알림 규칙의 시간대로 표시한 실행 시각도 포함됩니다. 예를 들면 `Weekday digest · 2026-10-12 09:00`입니다.

예를 들어 “Asia/Shanghai 시간으로 매일 23:00에 날씨를 확인하라고 알려 줘”라고 요청하세요. 응답 아래 카드에 알림의 이름과 반복 주기가 표시됩니다. ‘열기’를 누르면 오른쪽 사이드바에 세부 정보가 열립니다. ‘한 번’이 아닌 매일 23:00에 반복되는지 확인하세요. 일회성 알림은 전달 후에도 반복 알림으로 바뀌지 않습니다. 알림을 삭제하면 카드에 ‘삭제됨’이 표시되며 더 이상 열 수 없습니다.

모델 없이 만들려면 사이드바에서 ‘자동화 작업’을 열고 ‘새로 만들기’ 옆의 생성 방식 메뉴에서 ‘수동으로 만들기’를 선택하세요. 작업이 없을 때는 ‘새 자동화 작업’으로도 같은 편집기를 열 수 있습니다. 이 편집기에서는 기존 작업도 열 수 있으며 자동화 작업 이름, 지시, 실행 위치, 연결된 워크스페이스, 실행 시간을 설정합니다. 기본값은 브라우저의 시간대로 한 시간 뒤에 한 번 실행하고, 대화를 만들어 재사용하는 것입니다. ‘대화를 만들고 재사용’은 처음 실행할 때 만든 대화를 계속 씁니다. ‘실행마다 새 대화’는 매번 새 대화를 만들며 Host의 최소 실행 간격을 표시합니다. ‘연결된 워크스페이스’에는 등록된 워크스페이스와 각 디렉터리가 표시됩니다. 새 대화는 선택한 워크스페이스의 디렉터리를 사용합니다. 기본 워크스페이스가 등록되지 않았으면 첫 번째 항목을 선택합니다. 등록된 워크스페이스가 없으면 ‘그룹 없음’이 표시되고 Host의 프로젝트 디렉터리를 사용합니다. 새 대화에는 기본 프리셋이 적용됩니다. ‘만들기’는 작업을 추가하고 목록에서 선택합니다. ‘버리기’는 작업을 만들지 않고 편집기를 닫습니다. 입력한 날짜와 시간이 미래가 아닌 경우 등 Host에서 작업을 거부하면 입력을 유지하고 이유를 표시합니다.

‘새로 만들기’ 또는 같은 메뉴의 ‘대화에서 만들기’를 선택하면 현재 또는 가장 최근의 워크스페이스에서 새 대화가 열립니다. 그 대화에서 모델에게 작업을 만들도록 요청하세요.

## 작업 확인, 실행, 삭제

모델에게 알림 목록을 요청하면 모든 대화의 알림이 활성 상태부터 표시됩니다. ID를 지정해 개별 알림을 표시하거나 일시 중지, 재개, 삭제할 수도 있습니다.

사이드바에서 ‘자동화 작업’을 열면 대화를 열지 않고도 전체 세션의 알림을 볼 수 있습니다. 작업 이름, 지시, 연결된 대화 ID로 검색하고 작업 상태를 ‘전체’, ‘활성화됨’, ‘일시 중지됨’, ‘종료됨’으로 필터링할 수 있습니다. 목록은 예정 시각이 빠른 순으로 정렬됩니다. 각 행에는 작업 이름과 한 줄 요약이 표시됩니다. 요약에는 반복 주기, 일시 중지 또는 종료 상태, 활성 작업의 다음 예정 시각과 상대 시간이 표시됩니다.

세션의 작업에는 해당 세션으로 전달되는 작업, 매번 새 대화를 만드는 작업 중 가장 최근 전달이 그 대화에 도착한 작업, 해당 에이전트가 만들거나 편집한 작업이 포함됩니다. 실행 중이거나 보관된 상태가 아닌 세션에 활성 작업이 있으면 행에 시계 아이콘이 표시됩니다. 보관된 행의 해당 칸은 비어 있으며 상태는 호버 카드에서만 확인할 수 있습니다. 활성 작업이 있는 행에 포인터를 잠시 올려 두면 최대 두 작업의 반복 주기와 다음 실행 시각이 기기의 시간대와 상대 시간으로 표시됩니다. 열린 세션에 활성 작업이 있으면 헤더에 시계 아이콘이 표시됩니다. 작업이 하나면 오른쪽 사이드바에서 세부 정보를 열고, 여러 개면 각 작업의 세부 정보를 열거나 삭제할 수 있는 목록을 표시합니다.

작업을 선택하면 세부 정보가 열립니다. ‘규칙’에는 작업 이름, 다음 실행 시각과 상대 시간 또는 일시 중지·종료 상태, 지시, 반복, 실행 위치가 표시됩니다. 기존 대화로 전달하는 작업은 실행 위치에 현재 연결된 대화가 표시됩니다. 하단에는 연결된 세션이 표시되며, 매번 새 대화를 만드는 작업은 가장 최근에 실행된 대화가 표시됩니다. 세션을 사용할 수 있고 보관되지 않았다면 버튼으로 대화를 열 수 있습니다. 그 밖의 경우에는 버튼이 비활성화됩니다. 첫 실행에서 대화를 만들기 전에는 ‘생성 대기 중’이 표시됩니다. 기존 대화가 보관 상태이거나, 사용할 수 없거나, 로딩 중이면 ‘규칙’에 상태가 표시됩니다. 대화를 열 수 없어도 세부 정보를 보고 작업을 삭제할 수 있습니다. 작업을 찾아봐도 세션의 보관 상태는 해제되지 않습니다.

‘기록’을 선택하면 최근 저장 기록 20개를 불러옵니다. 각 기록에는 규칙의 시간대에서 발생한 시각(규칙에 지정된 시간대가 없으면 브라우저 시간대), 연결된 대화를 열 수 있을 때 표시하는 버튼, 저장된 지시가 포함됩니다. ‘펼치기’는 긴 지시의 전문을 표시합니다. 지시가 저장되지 않은 기록에는 현재 지시를 대신 표시하지 않습니다. ‘더 불러오기’는 다음 페이지를 추가합니다. 시스템 시계가 뒤로 이동해도 기록은 가장 최근에 저장된 순서로 표시되며 모델의 실행 결과는 담지 않습니다. 좌우 화살표와 Home/End 키로 탭의 포커스를 이동합니다.

기록 화면이 비어 있으면 조회는 성공했지만 저장된 기록이 없다는 뜻입니다. 불러오는 중, 요청 실패, 작업 없음, 이전 기록 커서가 잘못된 경우 각각 다른 메시지가 표시됩니다. 요청 실패나 작업 없음 응답에는 ‘다시 시도’를 선택하세요. 커서가 잘못되었으면 ‘새로고침’으로 최신 페이지를 불러오세요. 요청이 실패해도 이전에 불러온 기록이 경고와 함께 남을 수 있습니다. 새 전달 기록이 생기면 최신 페이지가 갱신됩니다. 다른 작업이나 화면으로 이동한 뒤 도착한 응답은 현재 화면을 바꾸지 않습니다.

보존 한도로 이전 기록이 삭제됐으면 마지막 페이지에 그 사실이 표시됩니다. ‘보존 규칙’에는 작업마다 보존하는 기록 수와 일수가 표시됩니다. 저장된 이력이 없는 오래된 작업에는 새 전달에서 기록이 추가될 때까지 최근 전달만 지시 없이 표시됩니다. 저장되지 않은 이전 기록과 당시의 지시는 복원할 수 없습니다.

활성 작업은 일정에 포함됩니다. 일시 중지되거나 종료된 작업은 다음 전달을 예약하지 않습니다. 한 번만 실행하는 작업은 알림이 대화 받은 편지함에 영구 저장되면 종료되고, 반복 작업은 규칙의 마지막 발생 후 종료됩니다. 종료된 작업을 보려면 작업 상태에서 ‘전체’ 또는 ‘종료됨’을 선택하세요. 세션 헤더와 행의 시계 아이콘, 호버 카드에는 활성 작업만 표시되므로 그곳에서 사라졌다고 작업이 삭제된 것은 아닙니다.

상세 화면의 ‘일시 중지’는 활성 작업의 이후 전달을 멈추고, ‘재개’는 중지된 작업을 다시 시작합니다. 자동화 작업 동작 메뉴의 ‘지금 실행’은 다음 예정 실행을 유지하면서 Host에 지시를 즉시 한 번 보내도록 요청합니다. 일시 중지되거나 종료된 작업에도 사용할 수 있습니다. 기존 대화 또는 한 번 만들어 재사용하는 대화로 보내는 작업이 대기 중이거나 실행 중이면 입력 필드, ‘변경 사항 저장’, ‘일시 중지’, ‘재개’, ‘지금 실행’, ‘작업 삭제’가 비활성화됩니다. 상세 화면에는 현재 상태와 해당 대화에서 관리하라는 안내가 표시되며 아래 버튼으로 대화를 열 수 있습니다. 실행마다 새 대화를 만드는 작업은 실행들이 독립적으로 진행되므로 이 이유로 비활성화되지 않습니다. 전달이 끝난 뒤 최소 전달 간격이 지나야 ‘지금 실행’을 다시 쓸 수 있습니다. 간격만 남았을 때는 버튼에 포인터를 올리거나 키보드로 포커스를 옮겨 언제 사용할 수 있는지 확인하세요. 이 사유로 Host가 실행을 거부하면 대기 중, 실행 중, 또는 방금 전달되었다는 상태가 표시됩니다. 전달 대상 대화가 보관된 동안에도 ‘지금 실행’은 비활성화됩니다. 작업 지시가 대기 중일 때 대화를 중지하면 다음 메시지, 다음 예정 실행, 또는 ‘지금 실행’이 시작될 때까지 지시는 대기열에 남습니다.

자동화 작업 동작 메뉴에서 ‘작업 삭제’를 선택하고 확인하면 이후 전달을 중단하고 목록에서 작업을 삭제합니다. 일시 중지되거나 종료된 작업도 삭제할 수 있습니다. 작업과 함께 저장된 전달 기록도 삭제됩니다. 삭제를 확인하면 앱 전체에 결과 알림이 한 번 표시됩니다. 성공하면 세부 정보가 닫히고, 실패하면 작업이 남아 다시 시도할 수 있습니다. 삭제해도 대화는 남으며 이미 대기열에 들어간 메시지는 취소하지 않습니다. 남은 작업 목록을 성공적으로 조회할 때까지 행이 표시됩니다. 조회가 실패하면 ‘다시 시도’로 목록을 새로 불러옵니다. 오류를 빈 목록으로 표시하지 않습니다.

## 작업 편집

모델에게 알림의 이름, 지시, 반복 규칙, 전달 대상의 변경이나 일시 중지, 재개를 요청할 수 있습니다. 변경해도 알림 ID와 저장된 전달 기록은 유지됩니다.

‘자동화 작업’에서 작업을 선택하면 이름, 지시, 실행 위치, 연결된 워크스페이스, 실행 시간을 변경할 수 있습니다. 일시 중지되거나 종료된 작업도 편집할 수 있습니다. ‘변경 사항 저장’을 선택하기 전에는 편집 내용이 로컬 초안에만 남습니다. 작업 ID, 최신 전달 확인, 저장한 모든 전달 기록은 유지됩니다. 규칙을 바꾸면 종료된 작업은 다시 활성화되며, 일시 중지된 작업은 계속 중지 상태입니다. 기존 대화에 전달하는 작업은 실행 위치에 현재 연결된 대화가 표시됩니다. 다른 옵션을 고르면 이후 실행부터 대화를 만들고 연결된 워크스페이스는 수동 생성과 같은 초기값으로 돌아갑니다. 워크스페이스가 같으면 저장된 프리셋을 유지하며 변경하면 새 워크스페이스의 기본 프리셋을 사용합니다.

- 한 번. 월간 달력에서 날짜를 선택하고 시·분·초 열에서 시간을 설정합니다. 지정한 시간대에 한 번 실행한 뒤 종료합니다.
- N분마다, N시간마다. 간격은 1 이상의 분 또는 시간 단위로 설정합니다. 작업을 저장한 분부터 간격을 계산합니다.
- 매일. 일 단위 간격을 설정하고 시·분 열에서 시간을 지정합니다.
- 매주, 월요일부터 금요일. 주 단위 간격을 설정하고 요일, 시, 분, 초를 지정합니다. ‘월요일부터 금요일’은 해당하는 5일을 한꺼번에 선택합니다.
- 매월. 월 단위 간격을 설정하고 1일부터 31일까지 날짜와 시·분·초를 지정합니다. 지정한 날짜가 없는 달에는 그 달의 마지막 날에 실행합니다.
- 사용자 지정. ‘사용자 지정 규칙’에 규칙 텍스트를 입력합니다. 다른 선택지에서 표현할 수 없는 규칙은 이 옵션에서 열립니다. 편집 가능한 규칙 텍스트가 없는 기존 작업은 원래 주기를 표시하며 새 규칙을 저장할 때까지 일정이 유지됩니다.

시간대 목록에는 최근 선택한 시간대가 먼저 표시되고 시스템 시간대에 표시가 붙습니다. UTC 오프셋, IANA ID, 도시 이름으로 검색할 수 있습니다. 기본 반복 옵션과 별도 시간대를 쓰는 사용자 지정 표현식에서 시간대 설정이 표시됩니다. 그 밖에는 사용자 지정 규칙 텍스트에서 시간대를 정합니다.

필드 편집은 로컬 초안에만 적용됩니다. 기존 대화가 대상인 경우 현재 연결된 세션을 다시 선택해 다른 편집 내용을 유지하면서 대상 변경을 되돌릴 수 있습니다. 편집 중에는 세부 정보 하단에 저장하지 않은 변경 사항과 ‘버리기’, ‘변경 사항 저장’이 표시됩니다. 저장은 변경한 필드만 한 번에 보내며 버리기는 저장된 값을 복원합니다. 실행 시간을 변경한 경우에만 새 규칙이 전송됩니다. 변경 사항이 있고 필드와 시간 설정이 올바를 때 저장할 수 있습니다. 사용자 지정 규칙이 잘못됐으면 초안을 유지하고 수정 안내를 표시하며 Host도 저장할 때 규칙을 검증합니다. 저장하거나 버릴 때까지 일시 중지, 재개, 지금 실행, 삭제는 사용할 수 없습니다. 저장 중에는 필드를 편집할 수 없습니다. 세부 화면에서 나가더라도 Host가 시작한 변경은 취소되지 않습니다.

다른 작업이나 페이지로 이동해도 저장하지 않은 초안은 유지됩니다. 목록을 새로고침하면 수정하지 않은 양식만 갱신됩니다. 수정 중인 양식은 모든 필드와 원래 버전을 유지합니다. 전달이나 다른 편집으로 새 버전이 도착하면, 작업이 다른 곳에서 변경됐다는 안내와 함께 저장이 비활성화됩니다. Host도 저장 시 버전을 검사합니다. ‘내 편집을 반영해 검토’는 변경한 제목, 지시, 시간, 전달 대상 그룹을 유지하고 다른 그룹에는 최신 값을 적용합니다. 같은 그룹이 다른 곳에서 변경되었다면 양식에서 내 변경 사항이 우선합니다. 이 동작은 아직 저장하지 않으므로 양식 전체를 검토한 뒤 저장하세요. ‘버리기’는 전체 초안을 최신 저장 값으로 교체합니다. 다시 저장하려다 실패하면 초안이 유지되고 재시도 안내가 표시됩니다. 결과를 알 수 없는 변경을 다시 시도하기 전에 작업을 확인하세요. 변경이 수락되면 목록이 갱신됩니다. 세부 정보를 닫거나 다른 작업으로 이동한 뒤 도착한 응답은 현재 화면을 바꾸지 않습니다.

## 실행 시간과 전달 방식

세션을 열지 않아도 알림은 저장됩니다. Host가 실행 중일 때 알림 시각이 되면 대상 세션을 복원하거나 만들고, 진행 중인 작업을 중단하지 않은 채 지시를 대기열에 추가합니다. Host를 다시 시작하면 저장된 작업을 확인해 기한이 지난 일회성 작업과 반복 작업마다 놓친 실행 중 가장 최근 한 번만 전달합니다. Host를 닫으면 다시 시작할 때까지 일정 처리가 중단됩니다. 같은 세션으로 보내는 반복 작업의 실행 시각이 겹치면 한 메시지로 묶일 수 있습니다.

IANA 시간대를 사용하는 반복 규칙은 현지 시각을 따릅니다. 존재하지 않는 시각은 건너뛰고, 같은 현지 시각이 두 번 나타나면 먼저 도래하는 때에 실행합니다. 새 규칙을 저장할 때까지 기존 일정이 유지됩니다. 고정 간격 알림은 생성 시각을 기준으로 하며 일간, 주간, cron 알림은 저장된 IANA 시간대의 현지 시각을 따릅니다. 자연어 요청에는 브라우저의 시간대가 적용됩니다. 시간대를 직접 지정하면 해석이 명확해집니다. 자동화 작업 페이지는 다음 실행을 브라우저의 시간대로 표시합니다. 규칙의 시간대가 다르면 반복 주기 설명에 규칙의 시간대를 표시합니다. 규칙에 시간대가 지정되지 않았으면 브라우저의 시간대를 사용합니다.

저장된 전달 기록은 메시지가 대화 받은 편지함에 저장되었음을 보여 줍니다. 모델이 요청된 작업을 완료했는지는 나타내지 않습니다. 받은 편지함 또는 작업 저장이 실패하면 기록이 추가되지 않습니다. 받은 편지함에 저장한 뒤 충돌하거나 작업 저장에 실패하면 이미 전달된 메시지가 기록되지 않고 다시 전달될 수 있습니다. 정확히 한 번만 전달된다는 보장은 없습니다. Host를 닫으면 아직 받은 편지함에 대기 중인 메시지를 버립니다. 저장된 기록은 남지만 모델에는 전달되지 않으며 Host는 다시 보내지 않습니다. 이 기록은 실행 이력이나 외부 알림으로 사용할 수 없습니다.

전달 확인이 추가되면 이전 기록을 정리합니다. Host는 추가한 확인 정보의 `deliveredAt`을 기준으로 과거 `deliveryHistoryDays` 동안 확인된 기록 중 최신 `deliveryHistoryRecords`개까지 유지합니다. 최신 확인 정보는 항상 남고, 기록 정리로 삭제된 이전 기록에는 접근할 수 없습니다. Host는 보존 기록을 메모리에 유지하고, 전달을 확인할 때마다 작업 데이터 행 전체를 다시 씁니다. 페이지 나누기는 반환 기록 수만 제한합니다. 저장된 이력이나 지시의 바이트 수는 제한하지 않습니다.

모든 알림은 모델의 `schedule_edit` 또는 자동화 작업 페이지를 통해 이름, 지시, 실행 시간과 대상의 편집, 일시 중지, 재개가 가능합니다. 두 기능으로 세션 간에 메시지를 중계할 수는 없습니다. 변경을 수행한 대화를 제외하고 에이전트가 로드된 관련 대화의 다음 모델 요청에 변경 알림이 추가됩니다. 오래된 세션 로그에만 기록된 알림은 자동으로 예약되지 않으므로 필요한 알림을 다시 만드세요. 이미 삭제한 작업 기록은 복구되지 않습니다.
