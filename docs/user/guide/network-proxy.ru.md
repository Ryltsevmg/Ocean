# Настройка сетевого прокси для OCEAN

<!-- USER_LANGUAGES_START -->
[English](network-proxy.md) | [中文](network-proxy.zh.md) | Русский | [日本語](network-proxy.ja.md) | [Español](network-proxy.es.md) | [Français](network-proxy.fr.md) | [Deutsch](network-proxy.de.md) | [Português](network-proxy.pt.md) | [한국어](network-proxy.ko.md)
<!-- USER_LANGUAGES_END -->

При запуске OCEAN читает стандартные переменные прокси и использует указанный сервер для исходящих запросов к моделям, веб-поиска, загрузки страниц и обращений к MCP по HTTP. Других настроек не требуется. Исключения перечислены в разделе о прямых подключениях.

<a id="export-the-variables"></a>

## Экспорт переменных

```sh
export HTTPS_PROXY=http://127.0.0.1:7890
export HTTP_PROXY=http://127.0.0.1:7890
```

Добавьте обе строки в профиль оболочки, чтобы их наследовал каждый запуск `ocean`, или запишите их в `$OCEAN_HOME/.env` (`~/.ocean/.env` по умолчанию), рядом с ключом API. Экспортированная переменная имеет приоритет перед этим файлом. Файл `.env` проекта не может задавать эти параметры. Он приходит с `git clone`, и OCEAN откажется запускаться, если репозиторий пытается определить маршрут трафика.

Если прокси требует учётные данные, укажите их в URL: `http://user:password@proxy.example:8080`. OCEAN не выводит URL. Диагностика называет только отклонённую переменную, без имени пользователя и пароля.

<a id="why-your-browser-is-proxied-but-your-terminal-is-not"></a>

## Почему браузер использует прокси, а терминал — нет

Это самый распространенный сюрприз, и он не специфичен для OCEAN. Не существует единого «системного прокси», которому подчиняется все программное обеспечение — есть три несвязанных механизма:

| Механизм | Какие программы его используют |
|---|---|
| Настройки прокси-сервера операционной системы | Safari, большинство нативных приложений для macOS, Chrome и Edge |
| Переменные окружения `HTTP_PROXY` / `HTTPS_PROXY` | `curl`, `git`, `npm`, `pip` и OCEAN |
| Режим TUN (виртуальный сетевой интерфейс) | Все, прозрачно |

Переключатель «системный прокси» в прокси-приложении, таком как Clash, записывает только первый. Браузеры подбирают его; инструменты командной строки никогда не видят его. Вот почему экспорт переменных является отдельным шагом, и почему включение режима TUN заставляет работать оба без каких-либо переменных вообще.

OCEAN не считывает настройки прокси операционной системы. Экспортировать переменные или использовать режим TUN.

<a id="choose-what-stays-direct"></a>

## Настройте исключения для прямых подключений

`NO_PROXY` задаёт список хостов, к которым нужно подключаться напрямую:

```sh
export NO_PROXY=internal.example.com,.corp.example.com,registry.local
```

Запись соответствует указанному хосту и всем его поддоменам. Например, `NO_PROXY=example.com` направляет запросы к `api.example.com` напрямую. Начальные `.` и `*.` допустимы и означают одно и то же. Запись может включать `:port`, а `*` отключает прокси для всех хостов.

**Диапазоны CIDR не работают.** Список обхода операционной системы часто содержит записи, такие как `10.0.0.0/8` или `192.168.0.0/16`; копирование их в `NO_PROXY` не имеет эффекта. Используйте имена хостов или суффиксы домена.

Включать `localhost` или `127.0.0.1` не нужно. OCEAN всегда подключается к loopback напрямую. Иначе обращения к собственному веб-интерфейсу и локальным серверам могли бы зациклиться через прокси.

<a id="limits-worth-knowing"></a>

## Ограничения, которые стоит знать

**Прокси SOCKS не поддерживаются.** При запуске OCEAN сообщает о значении `socks5://` и пропускает его. Для соответствующей схемы соединение остаётся прямым. Если указать `HTTPS_PROXY=socks5://…` вместе с рабочим `HTTP_PROXY`, запросы `https:` пойдут напрямую. Укажите HTTP-порт прокси-приложения. Как правило, он соседствует с портом SOCKS.

**Достаточно задать `ALL_PROXY`.** OCEAN использует его для обеих схем, хотя поведение Node и curl различается. Для ясности можно явно задать `HTTPS_PROXY`.

**Для корпоративного прокси, перехватывающего TLS, нужен сертификат.** Если прокси доступен, но запросы завершаются ошибкой сертификата, перед запуском укажите Node файл с сертификатами центра сертификации вашей организации:

```sh
export NODE_EXTRA_CA_CERTS=/path/to/corporate-ca.pem
```

Node читает переменную только при старте процесса. Экспортируйте её перед запуском `ocean`.

**Команды и дочерние процессы наследуют переменные прокси.** Это касается инструмента bash, `git`, `gh` и MCP-серверов, запущенных как дочерние процессы. Дочерняя программа Node использует установленную у неё версию рантайма. Node 22.21+ и 24+ учитывают эти переменные, старые версии подключаются напрямую. Если переменная содержит отклонённое OCEAN значение, например URL SOCKS, инструменты на Node также подключаются напрямую. `curl` и `git` по-прежнему читают это значение.

**Пароль в URL-адресе прокси-сервера также достигает этих инструментов.** `HTTPS_PROXY=http://alice:s3cret@proxy.example:8080` — это нормальная переменная среды, поэтому каждая команда, которую запускает OCEAN, включая те, которые пишет модель, может прочитать ее, а команда, которая печатает ее среду, вводит пароль на выходе, который сохраняется. Вот как переменная уже ведет себя для всего остального в вашей оболочке. Если это имеет значение, дайте прокси-серверу точку входа без учетных данных или проверьте ее каким-либо другим способом, чем в URL-адресе.

<a id="what-stays-direct"></a>

## Какие подключения остаются прямыми

Не каждый запрос OCEAN проходит через прокси-сервер:

- **Локальные подключения.** Адреса loopback всегда обходят прокси: `localhost`, весь диапазон `127.0.0.0/8`, `::1` и `0.0.0.0`. Сервис, который принимает только локальные подключения, недоступен через удалённый прокси.
- **Код, написанный моделью.** Процессы workflow и Node ptc-runtime не получают настройки прокси, поэтому код модели не может прочитать URL прокси с паролем. Если коду нужен прокси, его нужно настроить отдельно. Ограничения песочницы сохраняются.
- **Телеметрия использования.** Экспортёр OTLP использует собственный HTTP-клиент Node и подключается напрямую. Если прямой исходящий трафик заблокирован, отправка телеметрии завершится ошибкой. Это не влияет на работу OCEAN. Для отключения телеметрии задайте `OCEAN_TELEMETRY_MODE=DISABLED`.
- **`web_fetch` с частным IP-адресом в URL.** Запрос, например к `http://10.0.0.5/`, отклоняется до передачи прокси. То же происходит без прокси.

<a id="check-that-it-worked"></a>

## Проверьте, что это сработало

Попросите агента открыть страницу и проверьте журнал подключений в приложении прокси:

```sh
ocean --profile headless "fetch https://example.com and tell me the page title"
```

Если запроса в журнале нет, проверьте, унаследовал ли OCEAN переменные:

```sh
env | grep -i proxy
```
