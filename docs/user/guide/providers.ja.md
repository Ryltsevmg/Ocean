![The custom model API form: Provider ID, display name, base URL, API protocol, and API key](providers-custom-form.png)

プロバイダ ID は、リクエスト、保存セッション、モデルのデフォルト、およびクレデンシャルリファレンスが使用しているため、永続的です。 プロバイダーの名前を変更するには、新しいプロバイダーを追加し、古いプロバイダーを削除してください。 ディスプレイ名、ベースURL、プロトコル、認証、モデルの編集は可能です。

### 画像入力

でんぷん **設定 → モデル**, プロバイダを編集, 開く **カスタマイズされた設定**モデルの拡大と展開 **モデルオプション**. **入力タイプ** 容量フィールドの下の行を占める。 選択する **コンテンツ** 映像を受入れ、保存するモデルのため。 **テキスト** 継承された画像機能なしで新しいカスタムモデルで選択されます。少なくとも1つのタイプが選択されなければなりません。画像のみモデルのテキストをクリアする前に画像を選択します。

チェックボックスは保存します `input` pi-aiモデルおよび `inputModalities` 直接DeepSeekアダプター用。モデルを編集することもできます。 `$DSH_HOME/profiles/<profile>/cordis.patch.yml`; たとえば、このカスタム pi-ai プロバイダーは 1 つのテキストのみモデルと 1 つのビジョン モデルを宣言します。

これらの例は、プロファイルパッチ内のコンフィグフィールドを表示します。Cordis config オーバーライドは、完全なエントリコンフィグを置き換えます。既存のオーバーライドを編集するとき、他のプロバイダやフィールドを保存します。

```yaml
- id: llm-pi-ai
  config:
    providers:
      my-gateway:
        apiKeyEnv: GATEWAY_API_KEY
        api: openai-completions
        baseURL: https://gateway.example/v1
        models:
          - id: legacy-chat
          - id: vision-preview
            input: [text, image]
```

Pi-ai の `input` は `text` および `image` を受け入れ、そのモデルだけに適用します。 明示的な非空室選択が優先されます。 省略または空の `input` は、インストールされたカタログの入力タイプを継承し、 `defaultInput`のルートは、デフォルトは `[text]`です。 checkboxes は、行を開いたときに上書きを保存せずに、継承された値を表示します。

DeepSeek は、テキストのみで omitted `inputModalities` を扱い、空のリストを拒否します。 クリアイメージは、モデルの `imagePixelBudget` と `imageMaxBytes`も削除します。DeepSeekはテキストのみモデルに画像制限を拒否するからです。 後で画像を有効にし、カスタム制限が必要な場合は、これらの制限を再び設定します。

チェックボックスを編集した後の継承を復元するには、モデルの削除 `input` または `inputModalities` フィールドから `cordis.patch.yml`. **デフォルトを復元する** 他のモデルの編集を含むモデルのカタログのオーバーライド全体を取り除きますので、全カタログを復元したい場合にのみ使用します。

手で入力した全てのモデルが画像を取り込んでいる場合は、それぞれのモデルの代わりに、ルートに一度フォールバックをセットしてください。

```yaml
- id: llm-pi-ai
  config:
    providers:
      vision-gateway:
        apiKeyEnv: GATEWAY_API_KEY
        api: openai-completions
        baseURL: https://vision.example/v1
        defaultInput: [text, image]
        models:
          - id: first-model
          - id: second-model
```

`defaultInput` フォールバック、オーバーライドではなく、デフォルトは `[text]`: 組み込みのプロバイダでは、そのカタログが記述されていないモデルだけに答えるので、それらを持っているカタログモデルから画像を削除することはありません。そのモデルの1つを独自のものにする `input`. ビルトインプロバイダが明示されていない場合 `models` リスト、それを下書きする `modelOverrides`モデル id によってキーを付けられた:

```yaml
- id: llm-pi-ai
  config:
    providers:
      anthropic:
        modelOverrides:
          claude-sonnet-4-5:
            input: [text]
```

pi-ai の設定では、空のリストがそれを省略するのと同じ意味であるモデルの自身の `input`を除いて、すべてのリストは少なくとも 1 つの修飾名しなければなりません。 未知のモーダリティは、どこに書かれているか拒否されます。

どちらのフィールドもチェックではなく、エンドポイントに関するクレームを述べています。エンドポイントが宣言するモデルは、ここでは機能しません。プロバイダは、代わりにリクエストを拒否します。

### 働き方改革

モデルピッカーは、推論レベルを宣言するモデルのための **の努力** メニューを提供しています。 組み込みのプロバイダのモデルは、インストールされたカタログからレベルを継承し、DeepSeekのモデルはアダプターの水準を維持します。 ハンドで入力したモデルは、それらを追加するまで、誰にも宣言します。そのため、Effort エントリはメニューに表示されず、エンドポイントのデフォルトではモデルが考えるかどうかを決定します。

カスタムモデル API プロバイダーでは、 **設定 → モデル**: プロバイダーを編集し、 **カスタマイズ設定**を開き、モデルの **モデルのオプション**を拡張し、 **レベルを上げる**. 行は、オフ、低、中、高から始まります。 各行は、 **API 値** でレベルをペアリングし、デフォルトはレベル名に渡されます。モデルプロバイダーの API ドキュメントが異なるレベルをスペルする場所だけを変更します。 エンドポイントがサポートしているものに合わせて行を追加または削除し、オフの横に少なくとも1つのレベルを維持し、保存します。 スイッチをオフにすると、宣言が削除されます。

ページの書き込み `reasoningEfforts` でん `$DSH_HOME/profiles/<profile>/cordis.patch.yml`レベルを直接宣言することもできます。

```yaml
- id: llm-pi-ai
  config:
    providers:
      my-gateway:
        apiKeyEnv: GATEWAY_API_KEY
        api: openai-completions
        baseURL: https://gateway.example/v1
        reasoning: high
        models:
          - id: my-reasoner
            reasoningEfforts:
              off:
              high: high
              max: max
```

各キーはメニューの提供をレベルにし、その値が `reasoning_effort`としてワイヤーに送られる綴りです、従って `max: xhigh` は独自の語彙を持つゲートウェイのためのレベルを名前付けます。 `off` は、ほとんどのエンドポイントがパラメータの欠如ではないため、空にとどまるしかありません。 `reasoning` は、セッションがどれもピックアップしている間使用されるレベルです。ピッカーの努力を選択すると、モデルで、新しいセッションのデフォルトとして保存されます。

アナウンス `off` 左空は何も送信しません。これは、要求に考えるモデルを止めます。 `off` 与えられた値がその値をそのまま送信する `reasoning_effort` 代わりに。 言うまでもなく考えるモデル — DeepSeek V4 は OpenAI 互換ゲートウェイの背後にある、例えば — ニーズ `compat.thinkingFormat: deepseek`, なる `off` 送信する `thinking: {type: disabled}` 他のすべてのレベルは送ります `thinking: {type: enabled}` 努力の裏側:

```yaml
        models:
          - id: deepseek-v4-pro
            compat:
              thinkingFormat: deepseek
            reasoningEfforts:
              off:
              high: high
              max: max
```

ゲートウェイがそのレベルを失わないという組み込みプロバイダのモデル `reasoningEfforts: false` 以下は `modelOverrides`;それのための努力を選ぶことはそれからとして拒否されます `UNSUPPORTED_REASONING_EFFORT`. DeepSeekの独自のルートは、このどれも必要です:そのモデルは既に提供されている `off`, `low`, `high`, , , `max`, , , `llm-deepseek.reasoningEffort` デフォルトでは、ピッカーが次のものから始まります。

```yaml
- id: llm-deepseek
  config:
    reasoningEffort: max
```

```yaml
        api: openai-completions
        baseURL: https://gateway.example/v1
        compat:
          supportsDeveloperRole: false
          maxTokensField: max_tokens
        models:
          - id: my-model
```

ルートの `compat` は、そのモデルのデフォルトで、モデルの独自のウィンフィールドはフィールドによって行われます。そのため、ルートを休止することなく1つのモデルを修正することができます。

```yaml
        models:
          - id: my-model
          - id: my-reasoner
            compat:
              thinkingFormat: deepseek
```

インストールしたカタログの値をそのモデルに保持するもので、どのようなカタログが pi-ai の検出に落ちるのかを記述しません。 値に名前をつけるすべてのスイッチ: キー左空の (`supportsDeveloperRole:`) は無視されるのではなく拒否されます。空の値は、その場所で何も言っても、カタログが知っているものを消去するからです。 プロトコルの受け入れが拒否されず、メッセージは利用可能なものをリストします。

各スイッチはそれを宣言するプロトコルに属します。そのため、 `api` のスイッチは別の方法で無効にすることができます。つまり、プロトコルが提供しているメッセージ名です。 上記の `input` と同様に、スイッチは、チェックではなく、エンドポイントに関するクレームを述べています。ゲートウェイを1つ設定することは、単に異なるリクエストを送信する必要はありません。

各スイッチ、受諾値、およびそれを取るプロトコルは以下に記載されています。 `PiAiCompatProfile` お問い合わせ [生成される `dsh-llm-pi-ai` 構成の参照](../../config-catalog.md#oceanocean-llm-pi-ai) — ソースから派生するので、アダプターが受け入れるものの後ろに落ちることはできません。

<a id="troubleshooting"></a>

## トラブルシューティング

- **`MISSING_CREDENTIAL`** — プロバイダーのキーをモデルページから保存するか、参照された環境変数を供給します。
- **`UNKNOWN_MODEL`** — 設定されたモデルを選択するか、カスタムプロバイダーに欠落したモデルを追加してください。
- **利用可能なモデルをフェッチすると、401** が返されます。キーを確認してください。モデルディスカバリーはOpenAI互換の `GET /models` エンドポイントを呼び出します。モデルを手動で入力して、提供しないエンドポイントにモデルを手動で入力します。
- **利用可能なモデルをフェッチすることは、 `data` 配列と `models` オブジェクト** のどちらもレポートします。エンドポイントの一覧は、フォーマットのディスカバリーでは読みません。モデルを手で入力してください。
- **ゲートウェイは、キーと URL が正しい** であるが、すべてのリクエストを拒否します。そのリクエストは OpenAI の仕様と異なるためです。 `compat.supportsDeveloperRole: false` と `compat.maxTokensField: max_tokens` からルートで起動します。
- **理由のモデルだけが** に失敗 — pi-aiは、ゲートウェイが拒否する `developer` の役割としてシステムプロンプトを送信します。 設定 `compat.supportsDeveloperRole: false`.
- **Effort メニューは、** で入力したモデルには表示されません。 カスタムモデル API プロバイダーで、 **のレゾニング レベル** をモデルの **モデル オプション**でオンにします。 それ以外の場合は、 `reasoningEfforts` をモデルに追加します。 `cordis.patch.yml`.
- **`off` DeepSeekモデルを思考から停止しない** — 空の `off` 理由のないフィールドをまったく送信し、デフォルトで考えるエンドポイントは考え続けます。 設定 `compat.thinkingFormat: deepseek` モデルやルートで。
- **コンパットスイッチは、コロンの後に何も書かれていないキーである** を値しないため拒否されます。 それを値にするか、インストールされたカタログを保持するためのキーを削除します。
- **送信前に画像が拒否されます。** — モデルはイメージのモダリティを宣言しません。カスタムプロバイダーのモデルを `input: [text, image]`;DeepSeekの独自のルートで、設定されたカタログから画像処理可能なエントリを選択します()`deepseek-flash` デフォルトでは) ゲートウェイがそのモデルをイメージ入力で動作させることを確認します。
- **プロバイダは、イメージ** を運ぶリクエストを拒否します。このモデルは、そのエンドポイントが実際に機能しない画像を宣言します。 `image` は、そのリストから削除します。このモデルの `input`や、ルートの `defaultInput` は、新しいセッションを開始します。添付されたイメージはセッションログにとどまるので、セッションがオフになるまで同じリクエストが繰り返されます。
