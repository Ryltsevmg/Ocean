Эти три **примера, отключённые по умолчанию**, подключают одну систему памяти к OCEAN через [`@ocean/ocean-mcp-client`](../../../packages/mcp/mcp-client/README.md). Выберите одну или скопируйте ту же общую запись MCP для другого сервера.

Эти конфигурации третьих сторон приводятся только в качестве примеров совместимости. Их включение не подразумевает одобрения, рекомендации, партнерства или постоянной поддержки со стороны проекта Ocean.

<a id="what-ocean-does"></a>

## Что делает OCEAN

OCEAN анализирует выбранное наложение Cordis, запускает настроенную команду stdio или подключается к настроенному потоковому URL HTTP, обнаруживает инструменты MCP и выдает их как `mcp__<serverName>__<tool>`. OCEAN **не** скачивает сервер, не инициализирует его базу данных, не выбирает модель или провайдера эмбеддингов, не создаёт облачную учётную запись, не переносит данные и не управляет отдельной службой HTTP. Для stdio общий клиент запускает и останавливает ребенка с помощью жизненного цикла плагина OCEAN; для HTTP служба восходящего потока уже должна работать.

Перед запуском дочернего процесса мост stdio удаляет из его окружения переменные, имена которых обычно указывают на учётные данные, и все переменные `OCEAN_*`. Остальные переменные наследуются. Каждый пример явно добавляет только необходимые ему переменные. Если опциональная функция upstream нуждается в другом секрете, добавьте эту переменную в строку `config.env` вместо того, чтобы помещать секрет непосредственно в YAML.

<a id="choose-one"></a>

## Выберите один

| Система | Проверенная версия | Транспорт | Предварительное условие Upstream |
|---|---:|---|---|
| [Memorix](https://github.com/AVIDS2/memorix) | `memorix@1.3.0` (`500792cad3144142293bfbb20acb4841c9f7fcfa`) | stdio | Node 22.18+ `npm install --global memorix@1.3.0` |
| [Справочная память MCP](https://github.com/modelcontextprotocol/servers/tree/main/src/memory) | `@modelcontextprotocol/server-memory@2026.7.4` (`6dd0a683e198783e30feabf7abaf42f925bd18b1`) | stdio | `npm install --global @modelcontextprotocol/server-memory@2026.7.4` |
| [Engram](https://github.com/Gentleman-Programming/engram) | `v1.20.0` (`ba9e46ced152c37a7cb9e576153c41995873e2fc`) | stdio | Go 1.25.10+ и `go install github.com/Gentleman-Programming/engram/cmd/engram@v1.20.0`, или бинарный релиз |

<a id="enable-one"></a>

## Подключите выбранный сервер

Передайте OCEAN один файл конфигурации:

```sh
ocean web --patch "$PWD/apps/cli/config/examples/mcp-memory/memorix.cordis.yml"
```

Замените имя файла на `mcp-reference-memory.cordis.yml` или `engram.cordis.yml`. Путь может указывать на скопированный файл в любом месте на диске. Сервер памяти не присутствует в отправленной композиции, поэтому опускание `--patch` сохраняет все три отключенными.

Чтобы сохранить выбор между запусками, добавьте единственный патч `insert` из выбранного примера в пользовательский слой: `$OCEAN_HOME/profiles/<name>/cordis.patch.yml` для одного профиля или `$OCEAN_HOME/cordis.patch.yml` для всех профилей. Не перезаписывайте существующий файл. В нём могут быть другие пользовательские патчи.

<a id="provider-setup"></a>

## Настройка провайдера

<a id="memorix"></a>

### Memorix

```sh
npm install --global memorix@1.3.0
ocean web --patch "$PWD/apps/cli/config/examples/mcp-memory/memorix.cordis.yml"
```

Memorix работает в локальном эвристическом режиме без языковой модели или сервиса эмбеддингов. Дополнительных провайдеров настраивают в `~/.memorix/config.toml` или в файле проекта `memorix.toml`. Пример определяет Git-проект Memorix по рабочему каталогу OCEAN и использует стандартный каталог `~/.memorix/data`. Чтобы выбрать другой каталог, задайте `MEMORIX_DATA_DIR` до запуска OCEAN.

<a id="mcp-reference-memory"></a>

### Эталонный сервер памяти MCP

```sh
npm install --global @modelcontextprotocol/server-memory@2026.7.4
ocean web --patch "$PWD/apps/cli/config/examples/mcp-memory/mcp-reference-memory.cordis.yml"
```

Этот эталонный сервер хранит локальный граф знаний и предоставляет инструменты для работы с сущностями, связями и наблюдениями, а также чтения, поиска и открытия. Модель и сервис эмбеддингов ему не нужны. В примере JSONL хранится в `$HOME/.ocean-mcp-reference-memory.jsonl`, а не в каталоге пакета npm. Чтобы выбрать другой файл, задайте `MEMORY_FILE_PATH` до запуска OCEAN.

Сервер ищет подстроки без учёта регистра в именах и типах сущностей и в их наблюдениях. Семантического поиска, эмбеддингов, автоматических сводок, разрешения конфликтов и правил удаления старых данных нет.

<a id="engram"></a>

### Engram

```sh
go install github.com/Gentleman-Programming/engram/cmd/engram@v1.20.0
ocean web --patch "$PWD/apps/cli/config/examples/mcp-memory/engram.cordis.yml"
```

Engram сам выбирает хранилище и проект. По умолчанию он использует `~/.engram` и определяет Git-проект по рабочему каталогу OCEAN. Настройки можно переопределить переменными `ENGRAM_DATA_DIR` и `ENGRAM_PROJECT`.

<a id="optional-shared-model-instruction"></a>

## Дополнительная инструкция модели

Если описаний инструментов недостаточно и модель не обращается к памяти вовремя, добавьте к существующим инструкциям следующий текст. Он подходит для любого провайдера:

> Когда пользователь просит что-то запомнить, вызови инструмент записи в память. Если предыдущие сведения могут быть полезны, выполни поиск в памяти и используй подходящие результаты.

Эта инструкция дополняет системную настройку роли OCEAN.

<a id="verify-write-fresh-session-recall-and-use"></a>

## Проверьте запись, чтение в новой сессии и использование

Используйте одно уникальное значение и не меняйте область хранения провайдера в ходе проверки:

1. В сессии OCEAN A отправьте `Remember that my validation drink is lapsang-<unique suffix>.` Убедитесь, что модель вызвала инструмент записи провайдера и он отработал успешно.
2. Создайте сессию OCEAN B в том же работающем хосте. Не копируйте историю сессии A. Отправьте `What is my validation drink? Check memory.` Убедитесь, что модель вызвала инструмент поиска или чтения и получила сохранённое значение.
3. В той же сессии B отправьте `Use that preference to suggest one drink for the meeting.` Проверьте, что ответ использует значение из памяти.

Для проверки нужна новая сессия OCEAN. Перезапускать хост не требуется. При сбое дочернего процесса MCP клиент автоматически переподключается с увеличением задержки и синхронизирует инструменты заново. Пока соединение восстанавливается, инструменты остаются в списке, но их вызовы завершаются ошибкой. Когда попытки исчерпаны, инструменты удаляются из реестра, а переподключение прекращается до перезагрузки или перезапуска. Первичное обнаружение асинхронно. Дождитесь инструментов `mcp__...` от провайдера, прежде чем отправлять первый проверочный запрос.

<a id="bring-another-mcp-server"></a>

## Подключите другой сервер MCP

Скопируйте поля записи и укажите уникальные `id` и `serverName`:

```yaml
- insert:
    - id: memory-my-server
      name: '@ocean/ocean-mcp-client'
      config:
        serverName: my-memory
        transport: stdio
        command: my-memory-mcp
        args: []
        env: {}
        cwd: !!js process.cwd()
```

Для удалённого сервера используйте `transport: streamable-http`, `url` и `headers`. Установка, идентификация, аутентификация, модели, эмбеддинги, хранение данных и лицензирование относятся к ответственности провайдера.
