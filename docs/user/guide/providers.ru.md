Это руководство рассчитано на уже запущенный веб-интерфейс. Инструкции по запуску есть в [руководстве по разработке](../../development.md). Изменения модели вступают в силу со следующего запроса, перезапуск сервера не нужен.

<a id="configure-deepseek"></a>

## Настройка DeepSeek

Откройте **Настройки → Модели**. В карточке DeepSeek введите ключ API в единственное поле и сохраните его.

![Страница «Модели» с карточкой DeepSeek и кнопкой добавления провайдера](providers-models-page.png)

Ключи доступны только для записи. После сохранения страница получает описание с замаскированными данными. Сам секрет ей не передаётся. Ключ хранится в `$OCEAN_HOME/.credentials.yaml`, а настройки содержат только ссылку на эти учётные данные.

При сохранённом ключе и стандартной конечной точке список моделей берётся из API DeepSeek. Список загружается при первом обращении к моделям, обновляется в фоне примерно раз в десять минут во время использования и заменяется встроенным списком при ошибке загрузки. Изменения в разделе **Модели** внутри **Пользовательских настроек** сохраняют собственный список и отключают следование опубликованному. **Восстановить настройки по умолчанию** возвращает опубликованный список и загружает его заново. Когда используется опубликованный список, карточка показывает встроенные модели, поэтому новые модели видны только в меню выбора. Правила загрузки списка, подстановки и допуска описаны в [справке по провайдеру с ключом API](../../../packages/llm/llm-deepseek-api-key/README.md).

<a id="add-a-third-party-provider"></a>

## Добавить стороннего провайдера

Нажмите **Добавить провайдера моделей**. В карточке **Сторонний провайдер моделей** выберите провайдера из поставляемого каталога. В списке показаны идентификаторы, например `anthropic`, `openai`, `moonshotai` для Kimi и `zai` для GLM. Введите ключ API и сохраните. Установленный каталог задаёт протокол, конечную точку и список моделей.

Подсказка **?** у поля аутентификации объясняет приоритет сохранённого ключа и подстановку из окружения. Оставьте поле пустым, чтобы использовать сохранённый ключ или указанные переменные окружения. Зелёная подсказка означает, что переменная обнаружена. Жёлтая означает, что переменная не найдена. Введите ключ API или задайте указанную переменную. Статус без подтверждения означает ошибку чтения. Обнаружение не проверяет ключ и соединение. Эта проверка не охватывает файлы учётных данных провайдера, например профили AWS и Google Application Default Credentials. Для провайдеров без штатного входа по ключу, таких как `openai-codex`, поле показывается, только если в профиле явно задана ссылка на учётные данные.

В поле сохранённого ключа показан замаскированный фрагмент, а зелёная подсказка сообщает, что будет использован сохранённый ключ. Если можно скрыть хотя бы восемь символов посередине, остаются видны идентификатор до первого дефиса или подчёркивания, пять начальных и четыре последних символа ключа. Иначе точками заменяются весь ключ и идентификатор. Подсчёт ведётся по кодовым точкам Unicode. Сохранённый ключ нельзя показать, скопировать, вырезать или отредактировать частично. Ввод и вставка заменяют его целиком. Чтобы удалить сохранённый ключ и использовать окружение, нажмите Backspace или Delete, затем **Применить**. Если стереть весь текст нового ключа, сохранённый ключ тоже помечается к удалению. **Отмена** оставляет его на месте до сохранения. Если удаление отклонено, настройки сохраняются. Если удаление прошло, а настройки записать не удалось, приложение сообщает, что вернуть ключ нельзя. Нажмите **Применить** повторно, чтобы закончить, или **Закрыть**, чтобы оставить частичный результат. Удаление общих учётных данных затрагивает все функции с той же ссылкой. Если переменной окружения нет, провайдер останется без аутентификации. В пустом поле показаны пояснение об использовании окружения и одна подсказка об обнаружении переменной. При вводе замены приложение напоминает применить новый ключ. Если ключ отмечен к удалению, а маршрут объявляет переменную, приложение указывает переменную, которая будет использована после применения. Другие непустые поля не показывают статус аутентификации. Переменные адреса отображаются в поле **Базовый URL** и не считаются учётными данными.

Рядом с непустым новым ключом есть значок глаза. Нажмите **Показать секрет**, чтобы проверить ввод, и **Скрыть секрет**, чтобы снова замаскировать ключ. При изменении поле снова скрывается. Нативное поле пароля не предлагает вырезать текст. Выделите новый ключ целиком и нажмите Backspace, чтобы удалить его из поля, либо сначала покажите его. Сохранённый ключ доступен только для записи.

<a id="add-a-custom-model-api"></a>

## Добавить пользовательскую модель API

Выберите **Пользовательский API моделей** для ретранслятора, корпоративного шлюза, собственного сервера или провайдера вне установленного каталога. Укажите идентификатор провайдера в нижнем регистре, базовый URL, протокол API, учётные данные и хотя бы одну модель. **Протокол API** должен соответствовать шлюзу. Доступны OpenAI Chat Completions, OpenAI Responses, Anthropic Messages и Gemini API. В активном профиле параметр записывается в `cordis.patch.yml` как `openai-completions`, `openai-responses`, `anthropic-messages` или `google-generative-ai`. Базовый URL Gemini API включает версию API, например `https://gateway.example/v1beta`. У каждого провайдера один протокол. Если шлюз обслуживает два, создайте двух провайдеров.

![Форма пользовательского API моделей с идентификатором, именем, базовым URL, протоколом и ключом API](providers-custom-form.png)

Идентификатор провайдера является постоянным, потому что его используют запросы, сохраненные сеансы, модели по умолчанию и ссылки на учетные данные. Чтобы переименовать провайдера, добавьте нового провайдера и удалите старый. Имя дисплея, базовый URL, протокол, учетные данные и модели остаются редактируемыми.

<a id="discover-models"></a>

### Найти модели

В разделе **Каталог моделей** нажмите **Получить доступные модели**. Запрос использует базовый URL, протокол и ключ из формы либо сохранённый ключ существующего провайдера. В ответ откроется список с поиском. Модели из текущего списка уже отмечены. Отметьте те, которые хотите добавить, снимите отметки у тех, которые нужно удалить, и нажмите **Обновить список**. Настроенные модели, которых нет в ответе, сохранятся. Изменения записываются только при сохранении или создании провайдера.

Эта функция распознаёт распространённые форматы списков моделей. Если шлюз возвращает другой формат, запрос завершится ошибкой или пустым списком. Тогда добавьте идентификаторы моделей вручную. Для встроенного провайдера список всегда берётся из установленного каталога, даже если его базовый URL указывает на шлюз. Чтобы получить список от шлюза, используйте пользовательского провайдера.

<a id="select-a-model"></a>

## Выберите модель

Настроенные провайдеры появляются в меню выбора модели. Выбранная модель становится моделью по умолчанию для новых сессий. Если сессия уже отправляла запрос, она сохраняет модель, записанную в её журнале.

Чтобы изменить порядок моделей провайдера, откройте его в **Настройки → Модели**, разверните **Пользовательские настройки** и перетащите модель за ручку с тремя полосками. Можно также перевести фокус на ручку и нажать стрелку вверх или вниз. **Применить** сохраняет порядок, **Отмена** отменяет правки. Меню выбора модели использует сохранённый порядок для этого провайдера.

Если провайдер модели по умолчанию удалён, поле чата покажет кнопку **Выбрать модель**. Ввод станет доступен после выбора другой модели.

[`ocean-llm-pi-ai`](../../../packages/llm/llm-pi-ai/README.md) и [`ocean-llm-deepseek`](../../../packages/llm/llm-deepseek/README.md) Собственные прямые ссылки `cordis.patch.yml` конфигурация, разрешение каталога, элементы управления рассуждениями, учетные данные и ошибки адаптера.

На странице «Модели» доступны ключ API, отображаемое имя, базовый URL, протокол API и параметры каждой модели: идентификатор, имя, размер контекста, предел выходных токенов и типы входных данных. <a id="image-input"></a>

### Поддержка изображений

В разделе **Настройки → Модели** откройте нужного провайдера, разверните **Пользовательские настройки** и **Параметры модели**. Строка **Типы входных данных** находится под полями, задающими размеры контекста и ответа. Для модели, принимающей изображения, включите **Изображение** и сохраните. У новой пользовательской модели без унаследованной поддержки изображений по умолчанию включён **Текст**. Хотя бы один тип должен остаться выбранным. Для модели, принимающей только изображения, сначала включите изображения, затем выключите текст.

Флажки сохраняют `input` для моделей pi-ai и `inputModalities` для прямого адаптера DeepSeek. Можно также изменить модель в `$OCEAN_HOME/profiles/<profile>/cordis.patch.yml`. В этом примере пользовательский провайдер pi-ai объявляет текстовую модель и модель с изображениями:

Примеры показывают поля внутри патча профиля. Переопределение конфигурации Cordis заменяет настройки записи целиком. При изменении существующего переопределения сохраните настройки других провайдеров и полей.

```yaml
- id: llm-pi-ai
  config:
    providers:
      my-gateway:
        apiKeyEnv: GATEWAY_API_KEY
        api: openai-completions
        baseURL: https://gateway.example/v1
        models:
          - id: legacy-chat
          - id: vision-preview
            input: [text, image]
```

Поле pi-ai `input` принимает `text` и `image` и относится к отдельной модели. Явный непустой список имеет приоритет. Если `input` не задан или пуст, применяются типы из установленного каталога, а если в каталоге модели нет — `defaultInput` маршрута, по умолчанию `[text]`. При открытии строки флажки показывают унаследованные значения, но переопределение не сохраняется.

Если `inputModalities` не указан, DeepSeek считает модель текстовой. Пустой список отклоняется. При выключении изображений у модели удаляются `imagePixelBudget` и `imageMaxBytes`: у текстовой модели эти поля недопустимы. Если позже снова включите изображения, при необходимости задайте ограничения заново.

Чтобы вернуть наследование после изменения флажков, удалите у модели `input` или `inputModalities` из `cordis.patch.yml`. **Восстановить настройки по умолчанию** удаляет всё переопределение каталога, включая другие правки моделей. Используйте это действие только для сброса всего каталога.

Если все модели, добавленные вручную, принимают изображения, задайте одно запасное значение для маршрута:

```yaml
- id: llm-pi-ai
  config:
    providers:
      vision-gateway:
        apiKeyEnv: GATEWAY_API_KEY
        api: openai-completions
        baseURL: https://vision.example/v1
        defaultInput: [text, image]
        models:
          - id: first-model
          - id: second-model
```

Параметр `defaultInput` задаёт запасное значение `[text]`. У встроенного провайдера он действует только для моделей, которых нет в каталоге, поэтому не отключает изображения у моделей, уже поддерживающих их. Для такой модели ограничьте типы данных через её собственный `input`. Если у встроенного провайдера нет явного списка `models`, задайте настройку в `modelOverrides` по идентификатору модели:

```yaml
- id: llm-pi-ai
  config:
    providers:
      anthropic:
        modelOverrides:
          claude-sonnet-4-5:
            input: [text]
```

В конфигурации пи-ай каждый список должен называть по крайней мере одну модальность, за исключением собственной модели `input`, где пустой список означает то же самое, что опустить его.

Эти поля описывают заявленные возможности конечной точки. Проверка её возможностей не выполняется. Если модель объявляет поддержку изображений, которой у конечной точки нет, запрос отклонит провайдер.

<a id="deepseek-account-models"></a>

### Модели учетных записей DeepSeek

У моделей подключённого аккаунта DeepSeek список загружается из сервиса аккаунта, поэтому страница «Модели» не позволяет редактировать его напрямую. Настройте отдельную модель через `modelOverrides` в `$OCEAN_HOME/profiles/<profile>/cordis.patch.yml`. Поля совпадают с полями записи `models` DeepSeek. Незаданные значения берутся из списка аккаунта:

```yaml
- id: llm-deepseek-account
  config:
    modelOverrides:
      deepseek-flash:
        contextWindow: 524288
        maxTokens: 131072
```

Модель, которая нуждается в более новом Ocean, терпит неудачу с `CLIENT_UPGRADE_REQUIRED`, который называет версию для установки. [ссылка на поставщика учетной записи](../../../packages/llm/llm-deepseek-account/README.md) владеет правилами листинга, резервного копирования и аббревиатуры.

<a id="reasoning-effort"></a>

### Уровень рассуждений

Меню выбора модели показывает **Уровень рассуждений** для модели с объявленными уровнями. Модели встроенного провайдера наследуют уровни из установленного каталога, а модели DeepSeek используют уровни адаптера. У добавленной вручную модели уровней нет, пока вы их не настроите. До этого меню не появится, а режим рассуждений определит сама конечная точка.

Для провайдера с пользовательским API откройте **Настройки → Модели**, отредактируйте провайдера, откройте **Пользовательские настройки**, разверните **Параметры модели** и включите **Уровни рассуждений**. Изначально доступны уровни off, low, medium и high. Каждому уровню соответствует **Значение API**, которое отправляется с запросом. По умолчанию это имя уровня. Меняйте значение, только если документация API провайдера указывает другое имя. Добавьте или удалите строки в соответствии с возможностями конечной точки, оставьте хотя бы один уровень помимо off и сохраните настройки. Отключение переключателя удаляет объявление уровней.

Страница пишет `reasoningEfforts` в `$OCEAN_HOME/profiles/<profile>/cordis.patch.yml`, где вы также можете объявить уровни напрямую:

```yaml
- id: llm-pi-ai
  config:
    providers:
      my-gateway:
        apiKeyEnv: GATEWAY_API_KEY
        api: openai-completions
        baseURL: https://gateway.example/v1
        reasoning: high
        models:
          - id: my-reasoner
            reasoningEfforts:
              off:
              high: high
              max: max
```

Ключ задаёт уровень в меню, а значение отправляется как `reasoning_effort`. Например, `max: xhigh` указывает обозначение, которое понимает шлюз. Только `off` может остаться пустым, поскольку на большинстве конечных точек отключение рассуждений означает отсутствие параметра. Параметр маршрута `reasoning` действует, пока в сессии не выбран уровень. Выбранный уровень вместе с моделью запоминается для новых сессий.

Пустой `off` не отправляет параметр и отключает рассуждения только у моделей, которым для этого режима требуется явный запрос. Если у `off` есть значение, оно отправляется как `reasoning_effort`. Моделям, которые рассуждают по умолчанию, таким как DeepSeek V4 за OpenAI-совместимым шлюзом, нужна настройка `compat.thinkingFormat: deepseek`. Тогда `off` отправит `thinking: {type: disabled}`, а остальные уровни отправят `thinking: {type: enabled}` вместе с уровнем рассуждений:

```yaml
        models:
          - id: deepseek-v4-pro
            compat:
              thinkingFormat: deepseek
            reasoningEfforts:
              off:
              high: high
              max: max
```

Чтобы скрыть уровни встроенной модели, шлюз которой не поддерживает рассуждения, задайте `reasoningEfforts: false` в `modelOverrides`. Попытка выбрать уровень для такой модели завершится ошибкой `UNSUPPORTED_REASONING_EFFORT`. На собственном маршруте DeepSeek модели уже поддерживают `off`, `low`, `high` и `max`. Настройка `llm-deepseek.reasoningEffort` задаёт начальное значение меню:

```yaml
- id: llm-deepseek
  config:
    reasoningEffort: max
```

<a id="request-compatibility"></a>

### Совместимость запросов

Даже с действующим ключом и доступным адресом шлюз может отклонять запросы. По URL конечной точки pi-ai определяет формат запроса: роль системной инструкции, поле ограничения длины ответа и способ передачи уровня рассуждений. Если адрес неизвестен, pi-ai использует формат OpenAI. Многие OpenAI-совместимые шлюзы поддерживают лишь часть этого формата.

Две причины встречаются чаще всего. Для модели с рассуждениями системная инструкция отправляется с `role: "developer"`, которую многие шлюзы отклоняют. Ограничение длины ответа передаётся в `max_completion_tokens`, а некоторые серверы принимают только `max_tokens`. В форме таких полей нет. Измените их для маршрута в `$OCEAN_HOME/profiles/<profile>/cordis.patch.yml`:

```yaml
- id: llm-pi-ai
  config:
    providers:
      my-gateway:
        apiKeyEnv: GATEWAY_API_KEY
        api: openai-completions
        baseURL: https://gateway.example/v1
        compat:
          supportsDeveloperRole: false
          maxTokensField: max_tokens
        models:
          - id: my-model
```

Настройка `compat` маршрута задаёт значения по умолчанию для его моделей. Настройки модели переопределяют их по одному полю. Это позволяет исправить отдельную модель, сохранив параметры остальных:

```yaml
        models:
          - id: my-model
          - id: my-reasoner
            compat:
              thinkingFormat: deepseek
```

Если поле не задано ни у модели, ни у маршрута, применяется значение установленного каталога для этой модели. Для полей вне каталога действуют значения pi-ai. У каждого переключателя должно быть значение. Пустой ключ (`supportsDeveloperRole:`) отклоняется, поскольку он затёр бы значение каталога, не предложив замену. Если протокол не поддерживает имя переключателя, ошибка перечисляет доступные имена.

Переключатель действует только для тех протоколов, которые его объявляют. Настройка, допустимая для одного `api`, может быть отклонена для другого. Ошибка назовёт параметры этого протокола. Как и `input`, переключатель описывает вашу конечную точку, но не проверяет её возможности: он меняет только отправляемый запрос.

Переключатели, их значения и совместимые протоколы перечислены в `PiAiCompatProfile` в [сгенерированной справке по настройке `ocean-llm-pi-ai`](../../config-catalog.md#oceanocean-llm-pi-ai). Справка строится из исходного кода адаптера.

## Устранение неполадок

- **`MISSING_CREDENTIAL`.** Сохраните ключ провайдера на странице «Модели» или задайте указанную переменную окружения.
- **`UNKNOWN_MODEL`.** Выберите настроенную модель или добавьте нужную модель к пользовательскому провайдеру.
- **При получении списка моделей сервер возвращает 401.** Проверьте ключ. Функция обращается к OpenAI-совместимой конечной точке `GET /models`. Если её нет, добавьте модели вручную.
- **В ответе нет ни массива `data`, ни объекта `models`.** Функция получения списка не понимает этот формат. Добавьте модели вручную.
- **Шлюз отклоняет все запросы, хотя ключ и URL верны.** Его формат отличается от формата OpenAI. Начните с `compat.supportsDeveloperRole: false` и `compat.maxTokensField: max_tokens` в настройках маршрута.
- **Ошибки возникают только у моделей с рассуждениями.** pi-ai отправляет им системную инструкцию с ролью `developer`, которую шлюз отклоняет. Задайте `compat.supportsDeveloperRole: false`.
- **Для добавленной вручную модели нет меню уровня рассуждений.** Для модели не объявлены уровни. У пользовательского провайдера включите **Уровни рассуждений** в **Параметрах модели**. Для других провайдеров добавьте `reasoningEfforts` к модели в `cordis.patch.yml`.
- **При `off` модель DeepSeek продолжает рассуждать.** Пустой `off` не отправляет параметр рассуждений, поэтому модель следует настройке сервера по умолчанию. Укажите `compat.thinkingFormat: deepseek` для модели или маршрута.
- **Переключатель совместимости отклонён, поскольку у него нет значения.** После двоеточия ничего не указано. Укажите значение или удалите ключ, чтобы использовать установленный каталог.
- **Изображение отклоняется до отправки запроса.** Модель не объявляет поддержку изображений. Для модели пользовательского провайдера задайте `input: [text, image]`. Для маршрута DeepSeek выберите модель с поддержкой изображений из настроенного каталога (`deepseek-flash` по умолчанию) и убедитесь, что шлюз принимает изображения для неё.
- **Провайдер отклоняет запрос с изображением.** Модель объявляет поддержку изображений, которой нет у конечной точки. Удалите `image` из поля, которое разрешило изображения: `input` модели или `defaultInput` маршрута. Затем начните новую сессию. Вложение остаётся в журнале текущей сессии и отправляется при повторных запросах, пока сессия его использует.
