<a id="configure-deepseek"></a>

## Настройка DeepSeek

Откройте **Настройки → Модели**. В карточке DeepSeek введите ключ API в единственное поле и сохраните его.

![The Models page: the DeepSeek card, with Add model provider below it](providers-models-page.png)

Ключи доступны только для записи. После сохранения страница получает описание с замаскированными данными. Сам секрет ей не передаётся. Ключ хранится в `$DSH_HOME/.credentials.yaml`, а настройки содержат только ссылку на эти учётные данные.

С сохраненным ключом и конечной точкой по умолчанию модели DeepSeek следуют списку, который публикует API DeepSeek. Список загружается, когда модели впервые необходимы, обновляется в фоновом режиме примерно каждые десять минут во время использования и возвращается к встроенным моделям, когда они не могут загружаться. Редактирование **Models** в соответствии с настройками **Customized** сохраняет свой собственный список и перестает следовать за опубликованным; **Restore по умолчанию** следует за ним снова и перезагружает его. В то время как опубликованный список используется, карта показывает встроенные модели, поэтому недавно опубликованная модель появляется только в сборщике моделей. [API-ключ провайдера справочник](../../../packages/llm/llm-deepseek-api-key/README.md) владеет листинг, запасной вариант и правила аббревиатуры.

## Добавить стороннего провайдера

Выберите **Добавить модель провайдера**. Карта открывается на **Сторонний поставщик моделей**: выберите поставщика dsh-кораблей с - в списке показаны идентификаторы провайдера, такие как `anthropic`, `openai`, `moonshotai` для Kimi или `zai` для GLM - введите свой API-ключ и сохраните. Установленный каталог предоставляет конечную точку, протокол и список моделей.

Аутентификация **?** объясняет приоритет сохранения учетных данных и обратные эффекты среды. Оставьте ключ пустым, чтобы использовать сохраненные учетные данные или попробуйте перечисленные переменные среды. Зеленая подсказка идентифицирует обнаруженную переменную среды. Желтая подсказка означает, что переменная учетных данных не была обнаружена; введите ключ API или настройте указанную переменную. Неподтвержденный намек означает, что статус прочитанного не удалось. Обнаружение не подтверждает учетные данные или не проверяет соединение. Файлы учетных данных, управляемые провайдерами, включая профили AWS и учетные данные по умолчанию приложений Google, находятся за пределами этой проверки. Поставщики без нативной аутентификации ключа, такие как `openai-codex`, не показывают ключевое поле, если профиль явно не называет ссылку на учетные данные.

Сохраненные учетные данные отображают замаскированный предварительный просмотр во входе и зеленый намек на то, что сохраненный ключ будет использоваться. Предварительный просмотр сохраняет идентификатор перед первым дефисом или подчеркиванием, затем пять ведущих и четыре ключевых символа, только когда по крайней мере восемь средних символов остаются скрытыми; в противном случае весь ключ и идентификатор становятся точками. Счета используют точки кода Unicode. Сохраненные ключи не имеют кнопки «глаз» и не могут быть раскрыты, скопированы, вырезаны или частично отредактированы; ввод или вставка заменяет весь ключ. Backspace или Delete - этапы удаления всего ключа. Нажмите Backspace или Delete **Приложить**, чтобы удалить сохраненный оверрайд и использовать аутентификацию среды. Пустая замена также поэтапно удаляет сохраненный ключ. **отменить** Отказ в удалении оставляет настройки неизменными Если ключ удален, но настройки не работают, предупреждение сообщает, что удаление не может быть отменено; повторите **Приложить** Чтобы закончить настройки, или **Закрыть** Очистка общих учетных данных влияет на каждую функцию, используя одну и ту же ссылку. Без учетных данных окружающей среды поставщик не имеет аутентификации после очистки. **Оставьте пустой, чтобы использовать env как auth** и один намек на обнаружение, пока вход пуст. Заменяющий проект показывает напоминание о применении нового ключа. В ожидании удаления наименования переменной среды, используемой после применения, когда маршрут объявляет одно. Другие непустые входные данные не показывают текст статуса аутентификации. Переменные конфигурации адресов появляются под **Базовый URL** И не засчитывайте в качестве верительных грамот.

Редактируемый, непустый проект ключа имеет кнопку «глаз». Выберите **Показать секрет** , чтобы проверить, что вы набрали, и **Скрыть секрет** , чтобы снова замаскировать его. Смена входа маскирует его снова. Нативные поля паролей не предлагают вырезать; выберите черновик и нажмите Backspace, чтобы стереть его или раскрыть перед вырезанием. Хранимые учетные данные остаются только для записи.

<a id="add-a-custom-model-api"></a>

## Добавить пользовательскую модель API

Переключите карту на **Пользовательская модель API** для ретранслятора, шлюза компании, сервера с самостоятельным хостингом или любого провайдера, отсутствующего в установленном каталоге. Предоставьте идентификатор поставщика нижнего регистра, базовый URL, протокол API, учетные данные и, по крайней мере, одну модель. Протокол **API** должен быть тем, о котором говорит ваш шлюз, и выборщик предлагает четыре: OpenAI Chat Completions, OpenAI Responses, Anthropic Messages и Gemini API, хранящиеся в активном профиле `cordis.patch.yml` как `openai-completions`, `openai-responses`, `anthropic-messages`и `google-generative-ai`. Базовый URL-адрес Gemini API включает в себя версию API, такую как `https://gateway.example/v1beta`. Провайдер говорит по одному протоколу, поэтому шлюз, который обслуживает двух, нуждается в двух провайдерах.

![The custom model API form: Provider ID, display name, base URL, API protocol, and API key](providers-custom-form.png)

Идентификатор провайдера является постоянным, потому что его используют запросы, сохраненные сеансы, модели по умолчанию и ссылки на учетные данные. Чтобы переименовать провайдера, добавьте нового провайдера и удалите старый. Имя дисплея, базовый URL, протокол, учетные данные и модели остаются редактируемыми.

<a id="discover-models"></a>

### Найти модели

Под **Типовой каталог**Выберите **Получить доступные модели** Спросите конечную точку, какие модели она обслуживает. В запросе используется базовый URL, протокол и ключ, который в настоящее время находится в форме, или сохраненный ключ провайдера, и ответ открывает доступный для поиска выборщик: модели, уже включенные в список, начинают тикать, поэтому поиск, тикайте модели, чтобы добавить, отключайте те, которые нужно удалить, и выберите **Список обновлений**Настроенные модели конечная точка не перечисляет пребывания. Ничто не хранится до тех пор, пока вы не сохраните или не создадите провайдера.

Discovery читает форматы листинга, которые публикуют общие шлюзы, но не все ответы конечных точек в одном из них, поэтому рассматривайте его как удобство, а не как гарантию: когда он выходит из строя или ничего не перечисляет, добавьте идентификаторы модели вручную, и они работают одинаково. Встроенный провайдер всегда получает ответ из установленного каталога, даже когда его базовый URL указывает на шлюз, поэтому пройдите через пользовательского провайдера, чтобы увидеть, что шлюз действительно служит.

<a id="select-a-model"></a>

## Выберите модель

Настроенные провайдеры появляются в сборщике моделей. Выбор модели также делает ее по умолчанию для новых сессий. Сессия, которая уже отправила запрос, сохраняет модель, записанную в своем собственном журнале.

Чтобы изменить порядок модели провайдера, отредактируйте его в настройках **→ Модели**, откройте настройки **Customized**и перетащите трехстрочную ручку модели. Вы также можете сфокусировать ручку и нажать клавишу стрелки вверх или вниз. **Apply** сохраняет заказ; **Cancel** отменяет его. Выборщик модели следует за сохраненным заказом внутри этого провайдера.

Если сохраненный по умолчанию именует поставщика, который был удален, композитор отображает **Выбор модели** блокирует ввод до тех пор, пока не будет выбрана другая модель.

<a id="image-input"></a>

### Ввод изображения

В настройках **→ Модели**, отредактируйте провайдера, откройте настройки **Customized**и расширьте параметры модели **Model опции**. **Ввод типов** занимает свой собственный ряд ниже полей емкости. Выберите **Image** для модели, которая принимает изображения, и сохраните. **Text** начинает отбираться для новой пользовательской модели без унаследованных возможностей изображения. По крайней мере, один тип должен оставаться выбранным; выберите Изображение перед очисткой Текста для модели только для изображения.

В флажках сохранены `input` для моделей пи-ай и `inputModalities` для прямого адаптера DeepSeek. Также можно редактировать модель в `$DSH_HOME/profiles/<profile>/cordis.patch.yml`; например, этот пользовательский провайдер пи-ай объявляет одну текстовую модель и одну модель видения:

В этих примерах показаны поля конфигурирования внутри патча профиля. Переопределение конфигураций Cordis заменяет полную конфигурацию ввода; сохраняют другие поставщики и поля при редактировании существующей переопределения.

```yaml
- id: llm-pi-ai
  config:
    providers:
      my-gateway:
        apiKeyEnv: GATEWAY_API_KEY
        api: openai-completions
        baseURL: https://gateway.example/v1
        models:
          - id: legacy-chat
          - id: vision-preview
            input: [text, image]
```

Пи-ай `input` принимать `text` и `image` и применяется только к этой модели. Явный непустый отбор имеет приоритет. Опущенный или пустой `input` наследует установленные типы ввода каталога, а затем маршрут `defaultInput`который не выполняется для `[text]`Чекбоксы отображают эти унаследованные значения, не сохраняя переопределение, когда вы просто открываете строку.

DeepSeek рассматривает опущенный `inputModalities` как текстовый и отклоняет пустой список. Очистка изображения также удаляет `imagePixelBudget` и `imageMaxBytes`, потому что DeepSeek отклоняет ограничения изображения только для текстовой модели. Установите эти ограничения снова, если позже вы включите изображения и вам понадобятся пользовательские ограничения.

Чтобы восстановить наследование после редактирования флажков, удалите поле `input` или `inputModalities` из `cordis.patch.yml`. **Restore по умолчанию,** удалит всю оверрайд модели-каталога, в том числе и другие модификации модели, поэтому используйте его только тогда, когда вы хотите восстановить весь каталог.

Если каждая модель, которую вы вводите вручную, делает снимки, установите обратный эффект один раз на маршруте, а не на каждой из них:

```yaml
- id: llm-pi-ai
  config:
    providers:
      vision-gateway:
        apiKeyEnv: GATEWAY_API_KEY
        api: openai-completions
        baseURL: https://vision.example/v1
        defaultInput: [text, image]
        models:
          - id: first-model
          - id: second-model
```

`defaultInput` Он не является бременем, не является бременем, и не является бременем. `[text]`: на встроенном провайдере он отвечает только за модели, его каталог не описывает, поэтому он никогда не удаляет изображения из модели каталога, которая имеет их. `input`Когда встроенный провайдер не имеет явного `models` Список, напишите под `modelOverrides`, помеченный Model Id:

```yaml
- id: llm-pi-ai
  config:
    providers:
      anthropic:
        modelOverrides:
          claude-sonnet-4-5:
            input: [text]
```

В конфигурации пи-ай каждый список должен называть по крайней мере одну модальность, за исключением собственной модели `input`, где пустой список означает то же самое, что опустить его.

В обоих полях указывается претензия о вашей конечной точке, а не проверка ее.Модель, которая объявляет изображения, которые ее конечная точка не обслуживает, не поймана здесь; поставщик вместо этого отклоняет запрос.

<a id="deepseek-account-models"></a>

### Модели учетных записей DeepSeek

В учетной записи DeepSeek перечислены ее модели из службы учетных записей, поэтому на странице «Модели» не предлагается редактор моделей для нее. Настройте одну модель с `modelOverrides` в `$DSH_HOME/profiles/<profile>/cordis.patch.yml`; поля соответствуют входу DeepSeek `models` , а неустановленные поля сохраняют перечисленные значения:

```yaml
- id: llm-deepseek-account
  config:
    modelOverrides:
      deepseek-flash:
        contextWindow: 524288
        maxTokens: 131072
```

Модель, которая нуждается в более новом Ocean, терпит неудачу с `CLIENT_UPGRADE_REQUIRED`, который называет версию для установки. [ссылка на поставщика учетной записи](../../../packages/llm/llm-deepseek-account/README.md) владеет правилами листинга, резервного копирования и аббревиатуры.

<a id="reasoning-effort"></a>

### Обоснование усилий

Выборщик моделей предлагает меню **Effort** для модели, которая объявляет уровни рассуждений. Встроенные модели провайдера наследуют свои уровни из установленного каталога, а модели DeepSeek сохраняют уровни адаптера. Модель, которую вы вводите вручную, не объявляет об этом до тех пор, пока вы не добавите их, поэтому до тех пор запись Усилия не появляется в меню, и собственная конечная точка по умолчанию решает, думает ли модель.

На пользовательской модели API провайдера объявляют уровни в настройках **→ Модели**: редактируют провайдера, открывают настройки **Customized**, расширяют параметры модели **Model**и включают уровни **Reasoning**. Ряды начинаются с начала, низкого, среднего и высокого. Каждая строка сопоставляет уровень с значением API **, отправленным для него** , которое по умолчанию соответствует названию уровня; измените его только там, где документация API поставщика модели пишет уровень по-разному. Добавьте или удалите строки, чтобы соответствовать тому, что поддерживает конечная точка, сохраните хотя бы один уровень и сохраните. Выключение выключателя удаляет декларацию.

Страница пишет `reasoningEfforts` в `$DSH_HOME/profiles/<profile>/cordis.patch.yml`, где вы также можете объявить уровни напрямую:

```yaml
- id: llm-pi-ai
  config:
    providers:
      my-gateway:
        apiKeyEnv: GATEWAY_API_KEY
        api: openai-completions
        baseURL: https://gateway.example/v1
        reasoning: high
        models:
          - id: my-reasoner
            reasoningEfforts:
              off:
              high: high
              max: max
```

Каждый ключ представляет собой уровень, который предлагает меню, и его значением является написание, отправленное по проводу как `reasoning_effort`, поэтому `max: xhigh` переименовывает уровень для шлюза с собственным словарным запасом. Только `off` может оставаться пустым, потому что для большинства конечных точек отсутствие мышления является отсутствием параметра. Маршрут `reasoning` - это уровень, используемый, когда сессия не выбрала ни одного; выбор усилия в сборщике сохраняет его, с моделью, по умолчанию для новых сессий.

Ан `off` Оставшийся пустой ничего не посылает, что только останавливает модель, которая думает по запросу. `off` Данная ценность посылает эту ценность как `reasoning_effort` Вместо этого модель, которая думает, если ей не говорят не делать этого — например, DeepSeek V4 за шлюзом, совместимым с OpenAI, — нуждается в разработке. `compat.thinkingFormat: deepseek`которая делает `off` посылать `thinking: {type: disabled}` Все остальные уровни посылают `thinking: {type: enabled}` Помимо усилий:

```yaml
        models:
          - id: deepseek-v4-pro
            compat:
              thinkingFormat: deepseek
            reasoningEfforts:
              off:
              high: high
              max: max
```

Встроенная модель провайдера, шлюз которого не имеет оснований, теряет свои уровни с `reasoningEfforts: false` под `modelOverrides`; выбор усилия для него затем отклоняется как `UNSUPPORTED_REASONING_EFFORT`. Собственный маршрут DeepSeek не нуждается ни в чем из этого: его модели уже предлагают `off`, `low`, `high`и `max`, а `llm-deepseek.reasoningEffort` устанавливает по умолчанию сборщик, начиная с:

```yaml
- id: llm-deepseek
  config:
    reasoningEffort: max
```

<a id="request-compatibility"></a>

### Запросить совместимость

Шлюз может удерживать рабочий ключ на доступном адресе и все еще отклонять каждый запрос. pi-ai решает форму запроса - какая роль несет системную подсказку, какое поле ограничивает выход, как перемещается уровень мышления - с URL конечной точки, и адрес, который он не распознает, адресуется так, как если бы это был сам OpenAI. Большинство OpenAI-совместимых шлюзов отказываются от хотя бы одной вещи, которую OpenAI принимает.

Два из них составляют большую часть. Модель, которая заявляет, что рассуждение имеет свою систему подсказок отправлен как `role: "developer"`, который многие шлюзы отвергают сразу, и выходной колпачок отправляется как `max_completion_tokens`, который сервер, который знает только `max_tokens` отказывается. Форма также не имеет поля для них; исправьте их на маршруте. `$DSH_HOME/profiles/<profile>/cordis.patch.yml`:

```yaml
- id: llm-pi-ai
  config:
    providers:
      my-gateway:
        apiKeyEnv: GATEWAY_API_KEY
        api: openai-completions
        baseURL: https://gateway.example/v1
        compat:
          supportsDeveloperRole: false
          maxTokensField: max_tokens
        models:
          - id: my-model
```

Маршрут есть `compat` является по умолчанию для своих моделей, и собственная модель выигрывает поле за полем, поэтому одна модель может быть исправлена без пересчета маршрута:

```yaml
        models:
          - id: my-model
          - id: my-reasoner
            compat:
              thinkingFormat: deepseek
```

То, что ни один из этих наборов не сохраняет значение установленного каталога для этой модели, и то, что каталог не описывает, попадает под определение пи-ай. Дайте каждому переключателю имя значения: ключ, оставленный пустым (`supportsDeveloperRole:`), отклоняется, а не игнорируется, потому что пустое значение стерло бы то, что знает каталог, ничего не говоря на его месте. В имени, которое не принимает протокол, также отказано, и в сообщении перечислены те, которые доступны.

Каждый переключатель принадлежит протоколам, которые его объявляют, поэтому переключатель, действительный на одном `api` , может быть отклонен на другом — сообщение называет то, что этот протокол предлагает. Как и `input` выше, переключатель заявляет о вашей конечной точке, а не проверяет ее: установка одного шлюза на самом деле не требует просто отправки другого запроса.

Каждый переключатель, его принятые значения и протоколы, которые его принимают, перечислены в `PiAiCompatProfile` в [генерируемой конфигурации `dsh-llm-pi-ai` эталонной](../../config-catalog.md#oceanocean-llm-pi-ai) , которая получена из источника, поэтому она не может отставать от того, что принимает адаптер.

<a id="troubleshooting"></a>

## устранение неполадок

- **`MISSING_CREDENTIAL`** Храните ключ провайдера на странице Модели или подавайте переменную среды, на которую ссылаются.
- **`UNKNOWN_MODEL`** Выберите настроенную модель или добавьте отсутствующую модель к пользовательскому провайдеру.
- **Привлечение доступных моделей возвращает 401** — Проверьте ключ. Открытие модели вызывает OpenAI-совместимую конечную точку `GET /models` ; введите модели вручную для конечных точек, которые ее не предоставляют.
- **Доступные модели не сообщают ни о `data` ни ширины, ни `models` объект** — Список конечной точки находится в формате, который не читается. Введите модели вручную.
- **Шлюз отказывает в каждом запросе, хотя ключ и URL правы** — его форма запроса отличается от формы OpenAI. Начните с `compat.supportsDeveloperRole: false` и `compat.maxTokensField: max_tokens` на маршруте.
- **Только модели рассуждений терпят неудачу** — pi-ai отправляет свою системную подсказку в качестве роли `developer` , которую шлюз отвергает. `compat.supportsDeveloperRole: false`.
- **Меню Effort не отображается для модели, которую вы ввели вручную** — оно не объявляет уровни. На пользовательской модели API провайдер, включите **Разумные уровни** в модели **Варианты модели**; в другом месте, добавить `reasoningEfforts` к модели в `cordis.patch.yml`.
- **`off` Это не мешает модели DeepSeek думать.** - Пустое `off` не посылает никакого поля рассуждения вообще, и конечная точка, которая думает по умолчанию, продолжает думать. `compat.thinkingFormat: deepseek` по модели или маршруту.
- **Компакт-переключатель отклоняется как не имеющий значения** — ключ, написанный без ничего после толстой кишки. Дайте ему значение или удалите ключ, чтобы сохранить установленный каталог.
- **Перед отправкой** изображение отклоняется — модель не объявляет модальность изображения. Дайте настраиваемую модель поставщика `input: [text, image]`; по собственному маршруту DeepSeek выберите запись с поддержкой изображения из настроенного каталога (`deepseek-flash` по умолчанию) и подтвердите, что ваш шлюз обслуживает эту модель с помощью ввода изображения.
- **Провайдер отклоняет запрос с изображением** — Модель заявляет, что изображения ее конечной точки на самом деле не служат. Удалите `image` из любого предоставленного списка — `input`модели или `defaultInput` маршрута — затем начните новую сессию: прикрепленное изображение остается в журнале сеанса, поэтому тот же запрос повторяется, пока сессия не сдвинется с него.
