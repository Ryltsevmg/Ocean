# リバースプロキシの背後にあるWeb UIを公開する

`dsh --profile web` GUIをループバックポートで機能するため、別のマシンのブラウザが到達できないため、使用しているアドレスについて何も知りません。 外部の脚 — パブリックホスト名、TLS、およびそのパスプレフィックスがリスナーに転送する前にストリップを接頭辞するという逆プロキシ — `--public-url` は、ブラウザが使用する DSH を指示します。

```sh
dsh --profile web --public-url https://app.example/ui/ --trusted-host app.example
```

<a id="what---public-url-advertises"></a>

## 新着情報 `--public-url` 広告掲載

`--public-url` リクエスト `http://` または `https://` オプションのマウントプレフィックスでルートを正規化し、それをエンドに正規化 `/`. 印刷されたおよび開いた起動URLを供給します、 `DSH_WEB_URL`, エージェントのランタイムコンテキスト内の Web GUI URL . ウェブサーバは、オリジンルートのルートを提供し、マウントを学習しません。. `publicUrl` config フィールドは同じ広告を公開します。

<a id="what-the-proxy-must-do"></a>

## プロキシが何をすべきか

- **ブラウザの面で保存する `Host`.** 塀は受け取られた比較します `Host` 受理された機関に対して、プロキシはそれをリスナーのアドレスに書き換えるのではなく、それを変更しない転送します。
- **マウントプレフィックスをストライプします。** リスナーはオリジンルートのルートに応答しますので、 `/ui/api/...` のリクエストはそのまま到着する必要があります `/api/...`.
- **アップグレードを進めます。** リクエストと WebSocket のアップグレードは、 `Upgrade` と `Connection` ヘッダーがそのままでリスナーに到達する必要があります。 TLS は HTTPS を機能させるときにプロキシの外部の脚で終了します。
- **Cookie スコープを書き換えます。** バックエンドは、HTTP の問題のホストのみをプレーン `Path=/` クッキーなし `Secure`; プロキシが書き換える `Path` マウントへ(マウント)`/ui/`) および加えて下さい `Secure` HTTPS の脚に. 独自の TLS を提供するバックエンドのリスナーは、既にクッキーをマークします。 `Secure`なので、プロキシのみが書き換える `Path`.
- **ベアマウントをリダイレクトします。** `/ui/` は、セッションクッキーの起動トークンだけを交換し、 `/ui/index.html` は、提供されたドキュメントは、独自のディレクトリに対して URL を解決するので、既にそのクッキーを保持しているブラウザにドキュメントを提供しています。 `/ui` への要求は `/ui/`として着きます、そして除去されたバックエンドは外的な道を再建できません。

<a id="trust-the-authority-browsers-use"></a>

## 権限ブラウザの使用を信頼する

フェンスは、ループバック、リスナー独自のバインドアドレス、およびすべての権限の `--trusted-host` の名前を受け入れます。 他の権限で展開するブラウザーは、すべての API 呼び出しで 403 を取得しますが、プロキシが正しいので、 `--trusted-host`でブラウザ可視性権限を名前付けます。 `--public-url` でそれを広告するだけでなく、それを認めません。 ポートのないエントリは、毎回異なる結合トンネルに適している任意のポートにマッチします。 塀は要求だけを認めます;印刷されたURLおよび署名されたセッションクッキーの進水トークンはそれを認証します。 TLS は、終了したところ、このどれも変更しません。証明書は、サーバーをブラウザに識別し、ブラウザがサーバーにサーバーを識別します。

広告されたURLやフェンスがリスニングポート自体を保護するので、ポートを信頼できるプロキシやネットワークに制限します。

<a id="secure-the-external-leg"></a>

## 外部の足をしっかり止めて下さい

TLSをプロキシ、リスナー自体、または両方で終了します。 `--public-url` は広告を残します。 `http://` ブラウザの向きのルートは、プレーンテキストの起動トークンを公開します。 `https://` プロキシルートは、ブラウザからプロキシまで保護します。プロキシとリスナー間の暗号化は、リスナーのTLS構成に依存します。

リスナーを終了するには、 `--tls-cert` と `--tls-key`を渡します。各パスは、プロセス作業ディレクトリに対して解決します。証明書ファイルは、完全なチェーンと鍵ファイルが暗号化されていない PEM 秘密鍵を保持します。 DSH は、証明書を取得、更新、または時計の証明書を決して取得せず、キャリアはファイルを一度読み込みますので、それらを置き換えて、それらを変更するプロセスを再起動します。 スタートアップは、欠落または無効なペアで失敗し、HTTP に戻りません。 ブラウザは独自の信頼ストアと名前チェックを適用します。そのため、証明書はホスト名または IP を開いている必要があります。 デフォルトポートは3080です。 ネイティブ TLS はプロキシを必要としませんが、プロキシの展開と `--public-url` は独立してサポートされています。 TLSリスナーマークセッションクッキー `Secure`; ブラウザがこれらのクッキーを返すことができるように、パブリックブラウザのフェーシングレッグHTTPSを維持します。

印刷されたURLはプロセス認証を行なうので、意図したユーザーのみで共有します。
