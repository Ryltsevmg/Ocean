# 完全权限保留审批确认

[English](guide.md) | 中文

## 变更

Web、Desktop、Remote device 与 Connect 现在把完全权限预设与 `ask` 审批策略配对。选择完全权限会解除文件沙箱限制，但运行前需要询问的操作——GitHub 或 GitLab 写入，以及任何其他需要确认的工具——仍会询问你。该预设此前固定为 `never`，因此这些操作在没有人看到提示的情况下被拒绝。

`never` 策略与基础预设表没有变化，因为自动化配置没有可以回答问题的人：headless、ACP 与 SDK 会话继续把完全权限与 `never` 配对，保持确定性。只有交互式 bundle 覆盖这一组合。

审批策略为 `never` 的会话现在把受门控的操作报告为因审批提示被禁用而拒绝，而不再声称用户拒绝了它。被拒绝的沙箱升权同样不再把拒绝归因于用户。

## 迁移

1. 现有会话保留创建时记录的审批策略，因此升级前选择过完全权限的会话会在权限选择器中显示为 **Custom**，直到你再次选择完全权限。选择它会记录交互式组合并恢复标签；新会话从一开始就使用该组合。
2. 需要静默写入、不出现提示的 Web 或 Desktop 部署，必须在自己的补丁层中向 `@ocean/ocean-permission-presets` 的 `presets` 表加入一个 `approval: never` 的预设并选择它。交互式 bundle 不再读取 `OCEAN_PERMISSION_MODE` 来禁用审批。
3. 无人值守配置中的受门控操作仍然解析为拒绝，因为这些配置保留 `never`；只有措辞从人类拒绝变为审批提示被禁用。选择 `ask` 预设但没有组合应答者的配置会以“没有可用的审批通道”失败。
4. 升级后确认：选择 **完全权限** 时文件与命令执行仍然不受限，并且 GitHub 上的写入会在运行前询问一次。
