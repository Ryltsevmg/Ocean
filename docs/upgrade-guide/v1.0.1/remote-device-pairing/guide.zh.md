# 远程设备通过链接配对并持有具名权限

[English](guide.md) | 中文

## 变更

`ocean remote-device pair <label>` 签发一次性 `ocean://pair` 链接，取代手动复制的令牌。授权存活十分钟，只能使用一次，Host 只保存其哈希。Desktop 打开链接、请求确认，并把授权换成设备令牌；授权绝不会进入表单。`create` 和 `pair` 接受可重复的 `--scope`，把设备收窄到具名权限；网关只允许设备使用其活动登录权限的并集。Host 兼容性现在只要求 `version` 相同，不再要求 `commit` 相同。Desktop 把保存的连接保存为一台机器——Host 标识、一个令牌、通往它的所有 HTTPS 路由——记录格式为 `version: 3`，并通过 `HEAD /connect` 在不发送凭据的情况下询问 Host，以说明某个地址到达的是哪台机器。`ocean serve --tailscale-serve` 用 tailnet 名称发布 Host，Desktop 对话框可以通过 SSH 在 Linux 机器上准备并启动 Host。设置中新增 **设备** 页面，用于列出和撤销设备。

## 迁移

1. **把 Host 回退到 1.0.0 会让受限设备重新获得完全访问。** 1.0.0 的 Host 在第一次重写注册表时丢弃已保存的 `scopes`，并把没有权限的设备视为不受限。请在回退前于 1.0.1 中撤销所有限制过的设备。待处理的配对授权同样会被丢弃，因此 1.0.1 签发的链接会失效。
2. **把 Desktop 回退到 1.0.0 会丢失已保存的连接。** Desktop 1.0.0 无法读取 `version: 3` 记录并提供忘记它；请保留设备令牌以便重新输入，或者让 Desktop 保持在 1.0.1。
3. **在权限出现之前创建的设备保持全部权限。** 如果这不是有意为之，请创建一个权限更窄的设备并撤销旧的。
4. **尚未升级的 Host** 对 `POST /connect/pair` 回答 404 或 405；此时 Desktop 会改为要求输入设备令牌。
5. **同一版本的两个 commit 现在可以互相连接。** 由于不再比较 commit，未发布的改动请从同一个 commit 构建。
6. **已保存机器的第二个地址会成为该机器的一条路由。** 以另一个标识保存某地址会把路由迁移过去，并丢弃因此没有任何路由的机器。
7. **`--tailscale-serve` 会拒绝被占用的端口**，而不会替换其他站点；请传入空闲的 `--tailscale-serve-port`。已经提供目录的节点只允许 root 修改其 serve 配置，因此请让 `--tailscale-command` 指向运行 `sudo -n` 的包装脚本。

验证方法：用 `--scope sessions:read` 配对一台设备，在设置的 **设备** 页面确认它只持有该权限，并且可以列出会话但发送提示会被拒绝；然后在该页面撤销它，确认其打开的会话结束。
