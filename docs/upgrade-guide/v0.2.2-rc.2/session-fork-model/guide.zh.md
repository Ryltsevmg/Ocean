# 恢复 Session 时选择模型

[English](guide.md) | 中文

## 变更

当继承的模型不可用时，`session.fork` 会拒绝创建分支，除非请求通过 `modelSelection` 指定可用模型。此前，分支可能继承不可用的路由，并在运行首个提示词时失败。原 Session 及其历史保持不变。显式替代选择记录在子会话的继承历史之后，不会改写历史请求头，也不会提交提示词。

## 迁移

1. 为不可用路由创建分支的自定义客户端，必须在 `session.fork` 请求中提供 `modelSelection: { provider, model, reasoningEffort? }`，使用用户选择的可用模型。不要静默替换为默认模型，也不要编辑已存储的 Session 事件。
2. 在对话界面的模型路由或鉴权失败提示中，使用**在新对话中继续**，选择可用模型并确认。如果没有可用模型，请先配置模型再重试。鉴权失败并不表示另一个模型的凭据一定有效。
3. 确认独立的新对话包含所选模型及继承历史，而原对话仍可阅读且没有变化。请显式发送下一个提示词；恢复不会自动重试失败的操作。
