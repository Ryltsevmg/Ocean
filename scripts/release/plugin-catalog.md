# Prepare the approved plugin catalog

Use this procedure to prepare an index locally from reviewed package archives. The input is an explicit list, not a scan of the source repository. A directory, successful build or Git tag alone does not authorize release. Neither the generator nor the public index needs access to the private source repository.

1. Build each candidate from an identified source commit. Test installation and activation on its stated platforms and Ocean versions. Review the archive contents, dependencies, license notices and permissions to distribute them. Keep unpublished source, credentials and private build data out of the archive.
2. In the reviewed release inventory, write `schemaVersion: 1` and a `plugins` array. Include exactly one record per allowed package with `name`, exact `version`, `title`, `description`, `ocean` (the manifest's `engines.ocean` range), optional `platforms` (the manifest's `ocean.bundle.platforms`), local `archive` path and approved lowercase `sha256`. `title` and `description` are each a plain string or a locale map with a required `en` key and one non-blank bounded string per locale (120 characters for `title`, 2048 for `description`); the index carries them through unchanged for the Client to resolve in the active UI language. Paths are relative to the inventory unless absolute. Withdraw a package by omitting its record; `plugins: []` is a valid empty catalog.
3. Run `pnpm exec tsx scripts/release/plugin-catalog.ts --inventory <inventory.json> > current.next.json`. Use the output only on exit zero. A failed run cannot replace the published index. The command reads local files and does not publish anything.

   The output is index schema version 2: besides the reviewed metadata, the generator reads each approved archive and adds the package's own artwork as an inline `icon` data URL and its detail documents as `detail`. Those documents are selected exactly as a bundle page selects them, the `meta.detail` file per language, otherwise the README, and are stored for the languages that supply their own text. Images a document places beside itself are omitted, because the index serves no package files; a document left with no text is not stored. A declared icon that is missing, unreadable, larger than 256 KiB, or not PNG, JPEG, SVG, or WebP fails the run rather than shipping a card without artwork. Pass `--schema-version 1` to emit the metadata-only index that clients predating the artwork and long descriptions read.
4. With separate publication approval, stage the exact reviewed archives on `Ryltsevmg/Ocean`. Each archive is the `plugin.tgz` asset of a release tagged `plugin-<sha256>`. Mark plugin releases as not latest so they do not replace the latest Ocean application release. Do not move the tag or replace the asset. Verify the public downloads match the reviewed digests before updating the index.
5. Update both files in the `plugin-catalog` branch in one commit: `v1/current.json` from `--schema-version 1`, which released clients read, and `v2/current.json` from the default run, which the current composition reads. Publishing one without the other either hides the new fields from upgraded clients or breaks clients that predate schema version 2. Protect this branch and serialize catalog updates: a build for an older inventory must not overwrite a newer index. Confirm the public index names the intended offers and that withdrawal removes only the listing, not the already installed copies. Keep previously offered release assets available for audits; installed profiles use their retained verified archive.
