## 1. Резюме для руководства

Инженерная культура защит в Ocean заметно выше типичной для агентных harness: write-fence песочницы fail-closed, эскалации требуют явного однократного одобрения, инъекций команд из модельного ввода не обнаружено, персистентные данные пишутся атомарно с правами owner-only, сетевой периметр защищён от DNS rebinding/CSRF, криптография токенов и cookie корректна, канал установки официальных бандлов верифицируется по sha256, релизы подписаны Ed25519 с anti-rollback. Секретов в репозитории нет. Внешних неаутентифицированных путей к RCE или данным не найдено.

Однако выявлены **две системные асимметрии**, которые в сочетании с prompt injection образуют готовые цепочки компрометации:

1. **Песочница защищает целостность, но не конфиденциальность.** Чтение всего диска пользователя и сеть свободны во всех режимах, включая `read-only`; собственный стор секретов harness (`~/.ocean/.credentials.yaml`, plaintext) читается агентом и confined-процессами без эскалации. Прочитанные секреты навсегда оседают в логах сессий и по умолчанию выгружаются провайдеру модели.
2. **Асимметрия доверия к входящим инструкциям.** Web-контент маркируется как недоверенный, но instructions MCP-серверов попадают в системный промпт, project-скиллы и repo-AGENTS.md трактуются как доверенные инструкции, а в режиме `danger-full-access` исчезает последний технический шлюз — установка произвольного бандла выполняется без per-call подтверждения.

Дополнительно: приватные артефакты harness (аутентифицированный SSH control-master сокет, launch-request файлы раннера) лежат в общем writable `/tmp` на macOS (Seatbelt) и Linux (Landlock); сопряжённое remote-устройство де-факто равноправно владельцу (неограниченный shell + чтение любых файлов); в CI отсутствуют security-гейты (SCA/секреты/SAST); установленный Electron 44.7.0 имеет известный high-advisory с готовым патчем.

**Итог:** 6 High, 11 Medium, 19 Low, 8 Info — всего 44 находки. Большинство находок уровня High — не баги обхода, а границы дизайна и доверия; они честно задокументированы авторами частично, но продуктовое позиционирование «песочница» должно явно отражать, что конфиденциальность она не защищает. Приоритетные шаги — в разделе 6.

## 2. Системные риски (цепочки атак)

### Цепочка A — эксфильтрация секретов через prompt injection (H2 + H1 + M2 + M11)

Недоверенный контент (README клонированного репо, issue, веб-страница) инструктирует агента → `read ~/.ocean/.credentials.yaml` / `~/.ssh/id_rsa` / `~/.aws/credentials` (чтение не ограничено ни в одном режиме, denylist отсутствует) → содержимое попадает в контекст модели и в персистентный лог сессии → отправка наружу через `web_fetch` (приватные/внешние адреса не фильтруются) или ответ пользователя; параллельно полный лог сессии по умолчанию уходит в DeepSeek API (`dsh_session_log`, `enabled: true`). Scrub `DEEPSEEK_API_KEY` из окружения детей создаёт ложное ощущение защиты — ключ доступен на диске.

### Цепочка B — недоверенные инструкции → исполнение чужого кода (H4 + H5 + M1 + M6 + M7)

Злонамеренный репозиторий содержит `.agents/skills/*/SKILL.md` и вложенные `AGENTS.md` → каталог скиллов не показывает источник, тело вставляется дословно как «trusted local content» → агент следует инструкциям; либо MCP-сервер после безобидного первого подключения меняет описания инструментов по `tools/list_changed` без переодобрения (rug pull), а его instructions уже в системном промпте. В режиме DFA `plugin_manager install_bundle` проходит без approval (`requestedMode === effectiveMode`), бандл ставится из произвольного npm/git/http-реестра, его `cordis.patch.yml` может содержать `!!js` (полный eval с контекстом загрузчика), а host-only Cordis-плагин активируется в `node:vm` (осознанно не containment) без одобрения человека. Итог — персистентный код в Host-процессе.

### Цепочка C — confined-процесс → приватные артефакты в /tmp → выход за песочницу (H3)

В `workspace-write` на Seatbelt/Landlock confined-процесс имеет запись в host `/tmp`, где harness размещает: SSH control-master сокет (`mkdtemp('/tmp/ocean-ssh-')`, уже аутентифицированное соединение — как минимум форвардинги/DoS, вероятно команды на удалённом хосте вне локальной песочницы), одноразовые launch-request файлы Linux-раннера с полным env целевого процесса (гонка write→consume: подмена `NODE_OPTIONS`/`LD_PRELOAD` для sibling-процессов harness, которые могут запускаться без песочницы), spill-вывод и rc-файлы других сессий. Права 0700 не помогают: confined-процесс работает тем же UID. bwrap (`--tmpfs /tmp`) и Windows ACL (приватный per-session temp) не затронуты.

### Цепочка D — утечка device-токена → полный доступ хоста (M4 + M3)

Политика `remote-device` выдаёт `terminal/create` (shell «without Agent sandbox or approval restrictions»), `session/prompt`, `settings/update`, `credentials/set`, `workspaceFiles/read` без ресурсных привязок. Устройство читает `.credentials.yaml` (HMAC-секрет подписи owner-cookie) → подделывает owner-cookie → права владельца. Токены 256-битные и отзываемые, но окно компрометации не ограничено правами.

## 5. Что уже сделано хорошо

1. **Fail-closed по всему шву песочницы и эскалаций:** отсутствие/отказ раннера → структурированный отказ, не тихий passthrough; функциональные пробы цепочки; строго-восходящая лестница режимов; `allowed-once` на один вызов; проверка на исполнении, не в схеме; нет кэширования решений/auto-approve; Windows-раннер проверяет каждый Win32-вызов.
2. **Нет инъекций команд/аргументов из модельного ввода:** `bash -c`/`pwsh -Command` одним argv-элементом, корректный quoteArg под CommandLineToArgvW, `systemd-run --expand-environment=no`, SSH host-regex + escaping, `StrictHostKeyChecking=yes`/`BatchMode`/`ForwardAgent=no`, параметр `env` модели не принимается.
3. **Персистентность и файловые операции:** атомарные owner-only записи (0700/0600, attachment 0400), staging через `wx`+fsync, публикация `link()+unlink()` (no-clobber, разрывает hardlinks), инъективное кодирование недоверенных имён (zip-slip отсутствует), cleanup spill с проверкой владельца/sticky-бита/lstat, verify-before-delete реализован в коде (version-CAS + per-target locks), иммутабельный `header.cwd` как write-граница (`cd` её не двигает).
4. **Сетевой периметр:** единый Host/Origin/Sec-Fetch-Site-фенс на каждом `/api` и WS-upgrade (живые пробы: чужой Host/Origin → 403, WS без cookie → 401), запрет wildcard-bind на загрузке, 256-битные токены с SHA-256-верификаторами, HMAC-cookie с timingSafeEqual и authority-binding, fail-closed авторизация Gateway с ресурсной моделью, credentials API write-only, open-in-app allowlist + argv без shell, Electron sandbox/contextIsolation/nodeIntegration:false.
5. **Секреты и окружение:** права и атомарность credentials-файла с перепроверкой режима, диагностика никогда не цитирует значения, образцовый OAuth (PKCE S256, 32-байтный state с timingSafeEqual, одноразовый loopback-callback, issuer-binding, без refresh-токенов), единый env-scrub + пересборка `OCEAN_*`, запрет bootstrap-имён из любых `.env`, UI-маскировка распознаваемых credentials (`ui-secret-mask`).
6. **Доверенный канал установки и релизы:** sha256-верификация архивов каталога, пиннинг origin и release-assets, redirect-allowlist, re-check в момент коммита, откат при unexpected-package, build scripts по умолчанию заблокированы с явным per-package одобрением; подписанные релизы с anti-rollback (раздел 4).
7. **Транспортная гигиена web:** только http(s), запрет credentials в URL, ревалидация каждого same-origin redirect-хопа, byte/char/time/redirect-лимиты, content-type allowlist, HTML→markdown с вырезанием невидимых/активных элементов; credentialed-провайдеры с `redirect: 'error'` (токен не уходит на другой origin).
8. **Честная документация ограничений:** partial enforcement Windows, weaker containment macOS, остаточный TOCTOU, «network and process visibility outside this vocabulary»; SAFETY.md прямо заявляет экспериментальный статус и отсутствие security-аудита.

## 7. Ограничения аудита

- **Только статический анализ и немутирующие пробы.** Динамического pentest, фаззинга и runtime-эксплуатации не проводилось; цепочки C (SSH mux) и M10 (TOCTOU) помечены как гипотезы там, где финальный шаг не проверялся в runtime.
- **Внешние бандлы вне области:** провайдеры browser-use/computer-use и часть LLM-провайдеров поставляются отдельно; их enforcement-код в этом репозитории отсутствует (I1).
- **Установленное приложение** (`/Applications/Ocean.app`, GUI на 127.0.0.1:51655) может отличаться от исходников HEAD; живые пробы — косвенное свидетельство.
- **История git не сканировалась** на секреты полностью (только рабочее дерево и точечные проверки добавлений `.env`).
- Находки со статусом «субагент» имеют привязку file:line из профильного обзора, но не перепроверены ведущим аудитором лично; перед фиксацией в issue рекомендуется перепроверка.
- Аудит не является сертификацией: SAFETY.md проекта прямо заявляет experimental status; данный отчёт — первый систематический обзор, а не гарантия безопасности.
